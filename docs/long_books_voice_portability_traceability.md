# 长书、可迁移声音与原文追溯

本轮功能在 Vue 工作台和 CLI 中可用。启动工作台：

```bash
./run_ui.sh --ui vue
```

## 长书超过 LLM 上下文时

角色分析按章、按正文块顺序处理，不把整本书放进单次请求。人物索引先扫描所选章节范围；需要全书人物索引时选择全书范围。后续分段携带与当前正文相关的人物卡、章级叙述身份分析和相邻原文，限制这些附加信息的大小。

使用 `ROLE_LLM_CONTEXT_TOKENS` 设置分析模型的上下文预算，默认 16384，最小 4096。例如：

```bash
ROLE_LLM_CONTEXT_TOKENS=16384 ./run_ui.sh --ui vue
```

预算包含系统提示、正文、人物上下文、预留输出和安全余量。没有依赖某个供应商 tokenizer，而是按 UTF-8 字节数保守估算，因此中文请求可能小于模型实际允许的容量。请按模型的真实上限配置；单次输出另有预留。

超过预算或返回 `finish_reason=length/max_tokens` 时，正文继续按句子边界细分。输出还要通过 JSON、原文覆盖、人物姓名与证据校验。无法可靠分析的部分保留完整原文，标记为待复核的旁白；不会为了通过校验删除正文。

成功且通过校验的请求写入应用数据目录的 `.split_checkpoints/`。模型、服务地址、请求正文和提示版本参与缓存身份；人物索引另存已处理块和稳定人物 ID。停止或超时后，用相同书籍、解析参数、章节范围、模型和地址重新点击拆分，可复用有效结果。恢复是重新提交操作，不会在服务重启后自行启动任务；分析任务单次有 30 分钟上限。损坏或校验失败的结果重新计算。

长书声音保持一致的操作：

1. 在“设置 → 可迁移声音卡”完成固定文本试听，确认后保存版本。使用 MiMo 设计声音时，选 `mimo-v2.5-tts-voicedesign`，在“朗读要求”中填写声音描述。
2. 普通朗读在生成页选择声音卡；角色项目在人物声音面板逐人绑定，并复核确认剧本。
3. 描述生成的 MiMo 声音保存时，会把这次实际试听转成固定克隆参考，后续章节复用这份参考。不要每章重新生成设计音色。
4. 生成时固定声音卡版本、模型、服务地址和人物参数；人物绑定会锁定，自动选角尊重此锁定。修改参数或重拆后需重新复核。

这些措施固定声音身份与配置。模型服务本身仍可能存在合成随机性或升级差异，不能据此保证每次波形完全相同。

## 声音怎样迁移到其他 TTS

“OpenAI 格式”描述请求协议，不定义跨厂商共用的声音身份。本项目的 `openai` 是 MiMo 的历史别名，实际使用带 `audio` 的聊天接口；不能直接假设支持官方 `audio.speech`，也不能把不同厂商的同名音色当成同一声音。

本项目使用“逻辑声音 + 提供商绑定”，首批实现 MiMo / MiniMax。比如逻辑声音 `narrator` 可以同时保存这两个引擎各自试听确认的绑定。每个绑定限定提供商、模型和 HTTPS 服务地址；没有匹配绑定时明确报错，不静默选用其他声音。

操作流程：

1. 在“可迁移声音卡”新建逻辑 ID、名称和语言，选 MiMo，生成试听，听完勾选确认并保存。
2. 选择同一声音卡，切换 MiniMax，使用内置或自定义音色 ID 再试听、确认、保存，添加第二个绑定。
3. 需要 MiniMax 克隆时，展开“上传参考音并创建 MiniMax 克隆音色”，上传 10 秒～5 分钟、20 MB 以内的 WAV/MP3/M4A，填写新音色 ID，点击“上传、克隆并试听”，成功后确认保存。音色 ID 需 8～256 位，以字母开头、字母或数字结尾，中间可含数字、下划线、连字符。
4. 导出声音卡 ZIP，在另一台机器导入。配置目标机器自己的 API Key，再在生成页选择逻辑声音卡，系统按当前引擎解析匹配绑定。

声音卡保存的是服务端实际试听任务的参数快照与音频摘要，表单之后的修改不会改变已试听的绑定。每次保存产生内容摘要版本，旧版本保留。导出包包含 `voice.json`、试听和引用的参考音，文件以 SHA256 命名，不含 API Key 或本机绝对路径。导入验证版本、资源摘要、大小与文件路径。

MiniMax 的远程克隆 ID 属于当前账号；把 ZIP 发给另一个账号不会转移服务器上的音色所有权。包内保留克隆源参考音，可在目标账号重新上传、克隆、试听并更新绑定。上传或克隆请求中断、远端结果不明时，系统不会盲目重复计费操作；先在提供商控制台核对结果，再用已有 ID 或新的 ID 继续。相关接口：[文件上传](https://platform.minimax.io/docs/api-reference/file-management-upload)、[声音克隆](https://platform.minimax.io/docs/api-reference/voice-cloning-clone)。

不支持克隆的模型需人工选取并试听替代音色，再为同一逻辑声音保存绑定。目前 Edge、Qwen、Chatterbox、VoxCPM 继续使用各自原有配置，不会误套用 MiMo/MiniMax 声音卡。

CLI 普通朗读也可直接导入声音卡 ZIP：

```bash
python3 main.py book.epub output_dir \
  --tts openai --model_name mimo-v2.5-tts --output_format mp3 \
  --voice_profile narrator.zip --worker_count 1 --no_prompt
```

`--tts minimax` 时必须有该模型和服务地址的 MiniMax 绑定。全局声音卡适用于普通朗读，角色模式请逐人物绑定。声音卡朗读支持 MP3/WAV/FLAC。

## 结构化产物与追溯

新转换在音频输出目录同时生成：

| 文件 | 内容 |
| --- | --- |
| `manifest.json` | 书籍 SHA256、标题、作者、引擎、范围、本次运行 ID、状态、完成章节、保留原书的位置 |
| `chapters.json` | 章号、标题、清洗后的完整正文、正文摘要 |
| `source_map.json` | 段落 ID、原文、清洗后正文区间、源文件内部定位 |
| `roles.json` | 角色剧本和人物身份；普通朗读为旁白 |
| `voices.json` | 人物声音参数、版本、进入合成的角色参数及逻辑声音卡快照 |
| `timeline.json` | 章节音频摘要、采样时间区间、正文区间、角色/片段信息与关联段落 ID |
| `.source/original-<书籍摘要>.<扩展名>` | 原始上传书籍副本，与临时上传目录独立 |
| `.source/chapter-000001.json` 等 | 本次运行各章节的音频时间线，用于中断与失败后的汇总 |

各 JSON 的 `schema_version` 标明格式版本。书籍、正文和实际音频均校验摘要；重跑使用新的运行 ID，不把上次成功音频计为本次成功。停止或失败也刷新已完成部分。仅解析任务的状态为 `parsed`，没有音频时间线。

坐标规则：正文位置按 Unicode 码点计数，使用左闭右开区间 `[start,end)`，对应 `chapters.json` 中该章的正文。正则清洗、引用删除与替换会保留段落到原文的映射；`raw_start/raw_end` 表示清洗前提取文本的位置。段落映射不声称逐字强制对齐。

| 输入格式 | 可追溯精度 |
| --- | --- |
| EPUB | 书内 XHTML `href`、节点路径 `node_path`、节点原文 |
| DOCX | 原文段落零起始索引、段内字符范围和保留空白的原文 |
| DOC | 转换/提取后的段落位置；不声称恢复原始二进制 DOC 的页码或节点坐标 |

MiMo/MiniMax 普通朗读的 MP3/WAV/FLAC 及角色合成保存实际音频组装分片的采样范围，包含停顿后的时间位置；其他输出路径缺少分片坐标时明确标为整章定位。压缩编码的播放时间可能有少量编码延迟，未实施逐字强制对齐。

使用“资源库 → 选择输出目录 → 原文与音频溯源”：选择章节，点击段落跳到对应分片，播放时反向标记相关段落；同处可下载保留的原书。跨多个分片的段落跳到首个相关分片，多个段落共用一个分片时一同标记。旧输出没有这些元数据，需要重新生成后才能追溯。

接口 `GET /api/v1/library/source?folder=<输出目录>` 返回章节、段落、时间线及已登记的音频/原书文件 ID；文件下载使用现有 `/api/v1/files/<id>`。音频被外部替换或摘要不匹配时标为失效，不继续使用旧定位。
