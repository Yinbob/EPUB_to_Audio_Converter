# 可撤销人物记忆与优先审阅

研究原型接入 Vue 角色工作台，按项目启用。普通 V1/V2 项目继续沿用已有流程；启用需要具有连续原文区间的 V2 剧本。不会调用新的训练模型，排序分值也不是正确概率。

## 操作流程

1. 用 `./run_ui.sh --ui vue` 启动，上传书籍并生成或导入 V2 角色剧本。在「多角色配音 → 段落归属 → 优先审阅」点击「启用研究审阅」。该操作保留项目 ID、增加修订并清除整体确认。启用前的文件留作备份，后续以研究快照为准。
2. 点击「分析人物依据」。分析沿用 DeepSeek 分析服务配置，只校验分析凭据；不要求 MiMo/MiniMax TTS 凭据。后台任务沿用日志、spawn、停止和断点缓存，单次请求上限 120 秒，任务上限 30 分钟。停止或分析失败不会部分更新剧本。
3. 开始默认 10 分钟会话。队列显示疑点原因、证据、候选、影响章节及预计耗时。可以确认、修改、否定、跳过，也可继续原来的按章审阅。原文提及中的「父亲」等称谓只绑定具体范围。
4. 所有身份操作先预览范围和人物变化，再提交。合并保留源人物和声音记录；确认身份关系不会确认别名或相关对白。新建人物须明确勾选片段，并在「人物声音」中保存声音配置后才能确认生成。
5. 撤销关系使明确依赖的自动判断过期；仅接触相关上下文的片段进入低权重检查集合。人工逐段确认保留，新的矛盾进入冲突任务。点击「重新分析受影响片段」只生成草稿，逐项查看原文、前后人物及证据后应用。冲突项与人工确认项不能由草稿覆盖。
6. 在「复核与确认」看到剩余待审数后，仍需确认整本剧本。过期判断、失效来源及未配置声音会阻止确认或生成。会话计时、暂停、跳过和浏览不撤销既有确认。
7. 在「更新音频与导出研究记录」选择历史批次，点击「比较当前合成计划」。界面标明当前目标范围中已过期或未完成的章节；重新确认后可只返工这些章节。每次返工写到新的 `revision-<修订>-<批次 ID>/chapters-<开始>-<结束>/` 目录，保留原产物。资源库可下载修订章节；本版不自动拼装新旧整书。

页面隐藏、离开当前审阅组件、后台任务运行或主动暂停时不累计审阅时间。预算耗尽后暂停推荐，不会确认剩余项目；可以再增加 10 分钟或结束。暂停状态和已累计时间保存在会话中，页面卸载时会尝试提交最后一段计时。

## 状态与兼容性

权威状态在 `.studio/research/<project_id>/state.json`，格式版本为 `research_schema_version: 1`。一次 `atomic_json()` 同时保存当前 V2 剧本、关系、判断、事件及草稿；失败保留上一次完整快照。`.studio/projects.json` 只是可恢复索引。`.role_projects` 中的旧文件不再作为研究项目当前结果读取；V2 下载文件按当前修订生成，仍能由旧 V2 加载器读取。

快照包含：

| 字段 | 含义 |
| --- | --- |
| `script / sources` | 当前 V2 剧本及按章原文，保留书籍 SHA256、解析指纹及章节摘要 |
| `mentions` | 稳定 ID、Unicode 码点半开区间 `[start,end)`、原文文本、分析块 |
| `claims` | `mention_entity / same_entity / distinct_entity / narrator_entity`，端点、范围、证据、来源、创建及撤销修订 |
| `decisions` | 固定片段 ID、采用人物、候选、支持/反对依据、`proposed / unknown / human / stale`、分析版本 |
| `dependencies` | 明确引用的 `depends_on` 与本次实际提供的 `context_refs`；反向索引由状态重建 |
| `conflicts / context_checks` | 互斥身份、叙述范围、人工矛盾、来源失效及上下文检查集合 |
| `proposals` | 基础修订、输入摘要、建议、冲突、已应用片段、分析器版本 |
| `events / sessions / operations` | 用户动作、明确范围、前后差异、预算、抽样记录及请求幂等记录 |

关系状态为 `proposed / accepted / rejected / revoked`，独立于判断是否过期。合并使用有效关系投影 V2，不删除人物；有范围的关系只作用于被该范围覆盖的片段。历史破坏性合并无法还原，启用时记录 `history_incomplete`；可通过新建人物和重新分配恢复工作，系统不会猜测旧身份。

启用后保留固定片段 ID、正文、分段与停顿，不支持在同一研究项目重新拆分。原书、解析设置或正文变化需建立新项目，不能通过普通项目的宽松校验选项绕过。导出的研究快照和审阅记录用于回放及研究审计；本机资源路径会脱敏，研究快照导入恢复尚未提供。完整本机状态的恢复使用原始项目目录。

## 分析与依赖

实现集中在 `research_analysis.py`、`dependency_index.py`、`research_review.py`。当前按连续的单个固定片段建立请求，预算不足时削减人物卡和邻近上下文，再将过长片段递分，最后汇总回原片段。人物卡优先匹配当前原文姓名、相关关系候选和邻近采用人物，稳定 ID 负责同分排序。称谓不会自动加入全书别名。

程序拒绝伪造引文、越界坐标、未提供的人物/关系、漏片段、重复片段、已拒绝事实和循环依赖。不同子块的采用人物不一致时保留未知归属。新提及和关系使用内容生成稳定 ID。分析请求不把旧自动判断作为独立证据，只提供当前关系、人物卡和人工决定。

检查点绑定模型、服务地址、提示版本、原文和关系/人工决定摘要。工作进程只写结果；主进程检查修订后原子提交草稿。存储和应用均检查基础修订及输入摘要，旧草稿返回 409。部分应用保留剩余建议，其余项目修改会使草稿过期。依赖记录用于重检查，不表示完整揭示了模型内部因果过程。

## 排序与会话

策略参数位于 `audiobook_generator/role_script/review_policy_v1.json`：

| 因素 | 参数 |
| --- | --- |
| 风险 | 冲突 1.0、未知 0.9、关系未决/判断过期 0.75、无证据 0.55、有明确证据 0.25；取命中最大值 |
| 影响 | 直接依赖 1，每层传递乘 0.7，仅上下文暴露 0.25；同一片段取最大权重 |
| 耗时 | `20 + 0.03 × 展示证据字符数 + 8 × 备选数量` 秒，限制 20～180 秒 |
| 排序 | `风险 × 加权影响片段数 ÷ 预计耗时`；同分按首次原文位置和任务 ID |
| 抽查 | 默认每第 10 个推荐位置进行固定种子随机抽查，记录概率及队列版本 |

共享关系的片段聚为一个任务；完成后重算，已解决且无冲突的人工确认片段不再计入收益。会话记录推荐/手选、展示、跳过、答案和耗时。随机抽查种子包含会话种子、推荐位置及修订号；重放需使用相同输入、操作与配置。界面只展示原因、范围和时间。

## HTTP 与合成批次

接口挂在 `/api/v1/projects/{id}/research`，包含 `enable`、状态、`queue`、`preview`、`decisions`、`proposals/{id}`、`proposals/{id}/apply`、`sessions`、会话 `events`、`render-preview` 和 `export`。身份请求使用 Pydantic 判别联合。写请求携带 `revision`、`operation_id`；重复操作不重复提交，版本冲突返回 409。操作与普通角色编辑、确认、任务启动共用项目锁。

新增任务种类为 `research_analyze / research_reanalyze / research_regenerate`，仍通过 `/api/v1/tasks` 启动。`research_reanalyze` 默认选择过期和上下文检查集合，也可传 `segment_ids`。停止会终止进程组；迟到结果和重启前的未完成任务不会提交。

合成摘要保存实际正文、人物声音参数、参考文件内容摘要、模型、服务地址、格式、停顿及启用的质量设置，排除密钥与本机路径。解释或审阅记录变化不导致音频失效。任务快照记录批次实际生成的章节；每个连续范围的 `manifest.json` 只包含该范围的计划，并关联原批次。失败批次比较时会重试未完成章节。选择修订批次作为下一次基线时，它只代表该批次实际生成的章节，不代表已经拼成整书。

## 离线实验

无需凭据即可运行，默认预算 5、10、20 分钟：

```bash
./venv_audio_quality/bin/python -m audiobook_generator.role_script.research_experiment \
  --output /tmp/research-recorded --budgets 300,600,1200 --seed research-v1 --audit-every 10

./venv_audio_quality/bin/python -m audiobook_generator.role_script.research_experiment \
  --analyzer deterministic --output /tmp/research-fake \
  --budgets 300,600,1200 --seed research-v1 --audit-every 10
```

也可使用安装本项目依赖的 Python 3.10+。`examples/research_review/input.json` 是分析/排序输入，`gold.json` 是独立金标准，`recordings.json` 是录制响应。`build_fixture.py` 生成六个作者编写案例：同名、两次「父亲」指向不同人、错误合并与身份约束冲突、叙述视角、人工确认冲突和原文变更。

| 组别 | 人物记忆与修复 | 排序 |
| --- | --- | --- |
| A | 普通人物表退化基线：保留初始逐段结果，禁用关系投影及依赖传播，依次逐段修复，复用同一修复接口 | 原文顺序 |
| B | 可撤销关系及依赖传播 | 原文顺序 |
| C | 同 B | 风险 |
| D | 同 B | 风险、影响及耗时 |

四组共享同一输入、分析适配器、预算、种子和抽查设置。模拟审阅者只回答被选问题；后续修复仍经过真实的关系操作、过期标记、分析、草稿提交和应用接口。排序器与分析器不接收金标准。录制模式缺失响应会明确报错；假分析器只匹配输入人物卡中的明确说话标记，不访问录制文件或金标准。可用 `--input / --gold / --recordings` 换数据；记录键由片段 ID、当前请求正文和有效输入关系 ID 计算，响应必须符合分析契约。

金标准按案例保存 `segments: {片段ID: 人物ID}` 和 `claims: {关系ID: accept|reject|revoke}`。JSON 结果包含数据摘要、策略版本、种子、请求数、模拟耗时、已审问题、残余错误、误修复、重新分析片段、随预算变化的轨迹及事件；CSV 导出逐组逐预算的汇总。完整事件轨迹在 JSON 中。原文变更案例报告来源拒绝，不参与解释为算法修复收益。

这些数据和耗时均为模拟结果，用于流程与可复现性验证。真实小说标注、真实模型对比、排序模型训练和真人审阅收益不在本次验收中。当前分析块以单片段为主，未引入场景识别或完整文学知识推理；外部模型输出仍可能失败，失败会保留现有项目并要求复核。
