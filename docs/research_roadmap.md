# 多角色有声书生成：创新点、论文方向与下一步路线图

> 面向「把本项目做成一篇（或几篇）可发表工作」的调研与规划。
> 结论先行：**项目的真正差异化资产不在 UI、也不在接了多少个 TTS 引擎，而在「文本理解层（谁在说、怎么说）」和「声音编排层（谁来读、如何听得出区别）」，以及目前完全缺失的「评测层」。**

---

## 0. 一句话判断

项目已经完成了「EPUB/DOC → 分章有声书」的基本盘，并且通过未提交的 `audiobook_generator/role_script/` 模块 +
`deepseek_splitter.py`（1108 行）实现了**多角色剧本的自动生成 → 校验 → 角色音色分配 → 分段合成 → 整章拼接**闭环。

这套闭环里有一个**很干净、可辩护的核心技术主张**：LLM 只负责「提出假设」，本地确定性对齐器负责「把假设钉回原文」，
从而在保持 LLM 语义能力的同时，**数学上保证剧本逐字覆盖原文、不产生文本改写**。

这就是最值得写论文的种子。其余（UI、多引擎、部署）是加分项和 demo 材料。

### 0.1 必须守住的主张边界

“逐字覆盖”不等于“语义零幻觉”。当前校验器能证明：输出 segment 按顺序拼接后与源书正文一致；它**不能**证明
`role_id` 一定是正确说话人、两个别名一定是同一人物，或 `tone` 一定恰当。论文中应把两类性质分开报告：

| 性质 | 当前能否保证 | 应如何表述 / 度量 |
|---|---|---|
| 源文本保真、顺序与覆盖 | 能；确定性对齐与校验 | character coverage、normalized edit rate、对齐失败率 |
| 说话人归属 | 不能；由 LLM 提议 | quote/speaker Accuracy、macro-F1、unknown 召回 |
| 别名与跨章角色一致性 | 不能；当前没有全局实体层 | coreference B³ / CEAF、跨章 voice consistency |
| 声音可区分度与自然度 | 不能；当前为启发式选角 | 最小声纹距离、听众混淆率、偏好测试 / MOS |

因此推荐使用 **verifiable text fidelity（可验证文本保真）** 或 **grounded script rendering（有据剧本渲染）**，
不要笼统宣称“LLM 零幻觉”或“自动正确理解小说”。这个边界会让论文更严谨，也自然导向后续的实体记忆、置信度与人工审阅设计。

## 2. 关键缺口：这些缺口就是创新点

### 2.1 文本理解层

- **别名/指代未归并（最痛、最现实）**
  `宝玉 / 贾宝玉 / 宝二爷 / 怡红公子` 是同一人，但当前 LLM 很可能把它们拆成多个 `role_id`，
  于是**同一个人被分配了不同音色**，横向听感直接崩坏。这是当前系统最影响成品质量的问题，也是一个标准 NLP 题目
  （literary character coreference / entity linking）。
- **语气 `tone` 是自由文本，且跨引擎不一致**
  Schema 里有 `tone`，但不传给 MiniMax（官方无可验证情绪字段），MiMo 只能塞进 `instructions`。
  没有统一的情感/语气中间表示，也没有"同义 tone 归一"。
- **非对白话语体被一刀切进 narrator**
  书信、内心独白、诗歌/唱词、题记、脚注、剧本式旁白 —— 这些朗读风格和普通旁白不同，现在全丢给 narrator。
- **说话人消解只靠单章 LLM**
  跨章、跨卷的角色一致性没有持久记忆；长篇里角色名变体、临时称谓会漂移。

### 2.2 声音编排层

- **选角是贪婪启发式，不是优化**
  当前是"同性别音色池内轮转"。当角色数 > 池大小，必然重复；也无法回答"这 4 个女声里哪 2 个听感差异最大"。
- **无跨章节/跨卷音色一致性**
  每章/每次运行独立分配，续作里同角色可能换声。
- **本地克隆引擎未接入角色模式**
  VoxCPM / Chatterbox 都支持参考音频克隆 —— 天然适合"每个角色一份固定 reference audio"，
  能做到**离线、零 API 成本、音色稳定**，且这是相对商业 API 的差异化卖点。目前完全没接线。
- **停顿是固定 250ms**
  没有按话轮转换、段落、破折号、省略号建模停顿。

### 2.3 中文特有问题

- **多音字 / 专有名词 / 数字日期读音**：`行长`、`重`、`还`、人名地名 —— 现无发音词典或 G2P 干预。
  这是中文有声书"能听出来不专业"的最大来源之一。
- **标点与朗读节奏**：中文引号 `「」`、`""`、`——`、`……` 的对白边界与停顿未专门建模。

### 2.4 评测层（完全缺失 ← 这是发论文的关键一步）

- 没有任何**指代/说话人归属准确率**指标；
- 没有**音色可区分度**指标；
- 没有**自然度**自动或人工评测；
- 没有**基准数据集**。

> 一句话：现在这个系统"能跑、能演示"，但**无法被度量**。而论文 = 方法 + 可度量证据。
> **优先级最高的下一步不是继续加功能，而是把评测补上。**

### 2.5 统一问题定义：从“拆段 TTS”升级为“可验证叙事渲染”

建议把整个任务定义为：给定长篇叙事文本 $x$，产生角色实体集合 $E$、按原文位置切分的语篇单元 $U$、
每个单元的说话人/文体/风格标注，以及到声音配置的稳定映射。系统必须同时优化四件互相制约的事：

```text
文本忠实（不改字、不丢字）
      + 身份正确（谁在说、别名是否同一人）
      + 听感连贯（同人同声、不同人可分辨、节奏自然）
      + 可运营（低成本、失败可恢复、少量人工即可校对）
```

这也解释了为什么单独比较 TTS 的 MOS 不足以评估本项目：即使每一句音质很高，若“宝玉”在下一章突然换声，
或一句话错分给另一个角色，整本书的叙事可理解性仍然会下降。

## 3. 候选论文方向

下面每条给出：问题 / 核心主张 / 方法 / 数据与实验 / 投稿取向 / 复用现有代码的程度。

### P1（首选）可验证、跨章节一致的多角色剧本生成
**论题**：*"让 LLM 提出，让验证器与角色图裁决：面向长篇叙事的可验证多角色有声书生成"*

- **核心主张**：把 LLM 当**非可信提议器（untrusted proposer）**，用确定性字符级对齐器当**验证器/修复器**，
  在不牺牲语义拆分质量的前提下，保证**100% 文本覆盖率与零文本改写**；再用全书角色图约束身份一致性，
  把不确定项显式交给人工确认，而非静默猜测。
- **方法增量**（现有代码已具备 70%，需补 30%）：
  1. 现有严格/宽松/兜底三级对齐；
  2. **新增：别名归并（character coreference）**——LLM 给出别名簇，本地做一致性约束的实体链接，
     强制同一实体只有一个稳定的 `entity_id`；
  3. **新增：跨章角色记忆（voice bible）**——`entity_id -> voice/style/reference_audio` 持久化，
     新章节先复用已确认映射，再为新角色选角；
  4. **新增：话语类型分类**（对白/旁白/内心独白/书信/诗歌），分配合适的朗读策略；
  5. **新增：置信度与证据指针**——每个归属保存支持它的原文 span / 规则 / 模型置信度；低置信度、
     别名冲突和跨章冲突进入审阅队列；
  6. 对齐失败、角色未知、别名冲突的**可解释诊断**（错误类型学）。
- **实验**：
  - 数据：公版中文小说（四大名著、儒林外史、聊斋、老残游记…）+ 公版英文小说（Project Gutenberg，
    可对接已有 quote attribution 数据集如 PDNC）。
  - 指标：说话人归属 Accuracy/F1、逐字覆盖率（应恒为 100%）、角色清单 P/R、
    别名归并 F1、改写率、跨章音色一致率、审阅召回率与每千字人工分钟数、成本/token、长文鲁棒性（章数↑ 是否退化）。
  - 基线：直接让 LLM 输出 JSON（无对齐）、纯规则引号检测 + LLM、商用 API 直出。
  - 消融：去掉宽松对齐 / 去掉重试 / 去掉别名归并 / 去掉跨章记忆 / 随机审阅替代风险审阅。
- **投稿**：ACL / EMNLP 主会 *或* System Demonstrations（系统已完整，demo 命中率高）。
- **复用度**：★★★★★

### P2 自动选角作为约束优化
**论题**：*"听得出谁在说话：面向多角色有声书的音色分配优化"*

- **核心主张**：选角 = 在性别/语言/年龄/人设约束下，最大化角色两两听感可区分度的**指派问题**。
- **方法**：用说话人embedding（ECAPA-TDNN / WavLM / CAM++）度量音色距离；
  建模为 max-sum 二部匹配 / 二次指派（QAP）；可选学习到感知距离的映射。
- **实验**：自动指标（embedding 余弦间隔、最小成对距离）+ 人耳混淆矩阵 + 下游 MOS；
  对比现有贪婪轮转 / 随机分配。
- **投稿**：Interspeech / ICASSP / SLT（语音社区）。
- **复用度**：★★★☆（需要语音背景与人耳实验）

### P3 多角色有声书评测基准与指标
**论题**：*"如何评价一本 AI 多角色有声书？"*

- **贡献**：首个中文（+ 中英双语）文学多角色有声书基准：
  金标准说话人归属、别名簇、语篇类型、选角约束、人工听测与成套自动指标。
- **最小可发表版本**：先固定 5 本公版中文小说、每本 10~20 个连续章节；每一轮引语标注 speaker、
  aliases、是否可由局部上下文判定、文体类型与置信标签。不要以“LLM 预标注 + 人工抽检”代替金标准——
  测试集必须双人独立标注、裁决并报告一致性。
- **方法**：LLM 只可用于预标注；人工复核负责金标准。自动指标使用文本忠实度、说话人/别名指标、
  speaker embedding 距离与 UTMOS/NISQA 等质量代理；听测单独衡量“能否识别谁在说话”。
- **投稿**：LREC-COLING / ACL Resource & Evaluation。
- **复用度**：★★★（是 P1/P2 的共同基础设施）

### P3.1 建议的标注与评测协议（先做小，再扩展）

| 层 | 最小标注单元 | 金标准字段 | 主要指标 |
|---|---|---|---|
| 文本 | 连续原文 span | `start/end`、是否直接引语、是否允许切分 | exact coverage、normalized edit rate |
| 身份 | 引语 / 叙述性话语 | `speaker_entity_id`、`unknown`、支持证据 span | Accuracy、macro-F1、unknown recall |
| 实体 | 全书角色 | canonical name、aliases、性别（可 unknown） | B³、CEAF、pairwise F1 |
| 语篇 | span | dialogue / narration / monologue / letter / poetry | macro-F1 |
| 声音 | 人物对与章节 | voice ID、是否需保持相同声音、可接受约束 | consistency rate、最小距离、听众混淆率 |
| 人机协同 | 审阅任务 | 风险分数、是否真错、编辑耗时 | error recall@review budget、分钟/千字 |

建议把“听众混淆率”设计成任务而非泛泛 MOS：播放相邻两句话，询问听者“是否为同一角色 / 哪个角色在说话”；
这样才能测到多角色有声书最核心的叙事可理解性。MOS 与 UTMOS 仅作为音频质量的补充，不能替代该任务。

### P4 韵律与话轮建模
**论题**：*"从话语结构预测停顿与话轮转换"*

- 预测 `pause_after_ms`（按话轮/段落/标点/情绪），甚至支持打断与重叠；
- 评测：感知自然度、节奏正确率。
- **投稿**：Interspeech / ICASSP。
- **复用度**：★★★★（音频管线已就绪，只差模型）

### P5 系统 Demo 论文（低风险快速出成果）
**论题**：*"端到端可交互多角色有声书生产系统"*

- 卖点：EPUB → 自动剧本 → 可视化编辑/试听 → 多引擎渲染 → 成品；
  含本地离线克隆引擎（VoxCPM/Chatterbox）零成本路线。
- **投稿**：ACL/EMNLP/NAACL System Demonstrations。
- **复用度**：★★★★★（几乎只差把功能补齐 + 写论文）

### P6 风险驱动的人机协同审阅（可作为 P1 的独立贡献）
**论题**：*"只审阅会破坏叙事的片段：多角色有声书的风险感知人机协同校对"*

- **问题**：全书人工校对太贵，完全自动又会在隐式说话人和别名处留下高损害错误。
- **方法**：综合模型分歧、别名冲突、无显式说话人、长距离指代、角色声线冲突形成 risk score；
  将有限编辑预算优先分配到最高风险 span，并提供原文证据、候选角色和局部试听。
- **实验**：固定 5% / 10% / 20% 的审阅预算，比较随机抽检、按模型置信度、按完整风险模型三种策略，
  报告修正后的 F1、漏检严重错误率、每千字耗时和编辑主观负担。
- **价值**：很贴近出版工作流，也避免论文只在“模型分数”上竞争。

### 推荐组合

- **主线**：P1（方法）+ P3（基准）→ 一篇方法论文 + 一篇资源论文，互相引用。
- **语音线（若有条件）**：P2 / P4 投语音会议。
- **人机协同线**：将 P6 作为 P1 的关键实验，或独立投 HCI / NLP application 方向。
- **保底**：P5 demo，保证有产出。

## 6. 建议的 RoleScriptV2 与 Voice Bible（实现蓝图）

V1 已足够安全地渲染“某段文本由某个 role_id 朗读”，但它把“表面角色名、跨章人物实体和声音配置”混在一起。
不要破坏 V1 的已有文件；建议新增可向下编译到 V1 的 V2，或额外维护与剧本并列的 `voice_bible.json`。

```json
{
  "entities": {
    "jia_baoyu": {
      "canonical_name": "贾宝玉",
      "aliases": ["宝玉", "宝二爷", "怡红公子"],
      "gender": "male",
      "voice_profile": {
        "provider": "voxcpm",
        "voice_id": "preset_male_01",
        "reference_audio_sha256": "..."
      }
    }
  },
  "segments": [{
    "source_span": {"chapter_index": 1, "start": 123, "end": 156},
    "speaker_entity_id": "jia_baoyu",
    "discourse_type": "dialogue",
    "confidence": 0.86,
    "evidence_spans": [{"start": 105, "end": 112, "kind": "speaker_mention"}]
  }]
}
```

实现原则：

1. `source_span` 是事实来源；`text` 可由 source span 重建，避免编辑时复制出漂移文本。
2. `entity_id` 稳定于全书 / 全系列，`role_id` 可退化为渲染层兼容字段。
3. 每一条自动决定都应保存 `confidence` 与 `evidence_spans`；低置信度不强制指定人物。
4. `voice_profile` 与文本实体分离，允许同一书切换云端 / 本地引擎，亦能记录参考音频来源与授权。
5. V2 发布时提供迁移器、JSON Schema、固定夹具与 V1 回退，避免让已有用户剧本失效。

### 6.1 面向“证据 + 置信度 + 全书人物表”的具体实现流程

建议把现有的确定性文本对齐能力继续向上扩展，但要区分“找到了原文证据”和“证据足以证明归属”：前者可以通过字符区间验证，后者仍需人工金标准评测。

1. **固定文本坐标系**：完成 EPUB/DOC 解析、清洗和章节规范化后，才对章节规范文本建立字符偏移。每个 span 明确使用 Unicode code point 坐标，并绑定 `book_sha256`、章节文本哈希、解析器/规范化版本；避免混用 EPUB 原始字节偏移与清洗后的字符偏移。分段文本应能由源 span 取回。
2. **角色身份与声音身份分离**：为全书人物分配稳定 `entity_id`，为渲染声线分配独立 `voice_profile_id`。别名是带来源的 mention/alias 记录，不直接作为实体主键；角色合并、拆分、确认和撤销都保留历史。
3. **逐段保存结构化证据**：每个说话人判断保存候选人物、决策状态（`proposed/confirmed/unknown`）、证据 span、证据类型（显式说话标签、对话轮次、代词/共指、全书人物记忆）、关系标签（例如 `said-by`）、模型/提示版本及运行记录。只保存可核验的原文片段和位置，不保存或展示模型隐藏推理链。
4. **人物记忆增量更新**：每章先从已确认的全书人物表检索相关人物卡片，再判断新 mention 是旧实体、新实体还是待消歧项。人物卡片记录 canonical name、已确认别名、区分性描述、关系、首次/最近出现章节和证据来源。只有人工确认或达到经过验证的高置信门槛的事实才可自动写入长期记忆。
5. **置信度门控而非强制猜测**：综合说话标签、上下文距离、对话轮次、共指模型分数、独立模型分歧等信号形成分数；不能把 LLM 自报的“0.95 置信度”直接当真实概率。用按整本书留出的人工标注集做温度缩放或 isotonic 等校准，并按阈值分为自动接受、人工复核和 `unknown`。评测 ECE/Brier、precision-at-auto-accept、risk-coverage 曲线和 unknown 召回；体裁/作者变化时应检查是否需要重新校准。
6. **固定 voice bible 并审计合成配置**：在 `entity_id -> voice_profile_id` 映射中记录 Provider、模型/版本、voice ID、固定参考音频哈希、稳定身份参数、可变情绪参数和人工锁定状态。角色声线在全书固定，段落情绪单独控制；模型版本或参考音频改变时显式提示。固定音色 ID 仍需实测多次合成的韵律漂移。
7. **把 UI 做成低成本校对工具**：按预计错误风险排序待审片段，显示原文上下文、证据高亮、候选人物、置信状态及局部试听；支持确认说话人、合并/拆分人物、锁定音色。人工修改写入审计记录，并只重合成受影响段落。

V2 关键字段示意（置信值仅为结构示例，不代表建议阈值）：

```json
{
  "segment_id": "ch03_seg018",
  "source_span": {
    "chapter_id": "ch03",
    "start": 4281,
    "end": 4315,
    "coordinate": "canonical_chapter_codepoint"
  },
  "speaker": {
    "entity_id": "char_002",
    "status": "proposed",
    "confidence": 0.87,
    "evidence": [{
      "type": "explicit_speech_tag",
      "span": {"chapter_id": "ch03", "start": 4316, "end": 4320},
      "relation": "said-by"
    }]
  },
  "voice_profile_id": "voice_002"
}
```

`source_span` 可由当前 `_reconcile_segments` 的原文映射扩展；V1 保持兼容，V2 或并列的 voice bible 承载新增信息。置信度阈值须由验证集上的精确率/覆盖率权衡确定。

| 场景 | 用户的实际问题 | 可落地功能 | 可研究的结果变量 |

| 视障、阅读障碍与老年读者 | 单一音色长时间听读难以跟踪人物和章节 | 稳定角色声线、章节导航、速度与发音个性化 | 人物理解题正确率、完成率、主观负担 |

## 8. 风险与建议

1. **不要用"接了多少 TTS 引擎"当论文卖点**——那是工程集成，不是研究贡献。
2. **版权**：中文现代小说不可自由使用；评测集务必选**公版**文本并保留出处与许可。
3. **可复现性**：商业 API（DeepSeek/MiMo/MiniMax）版本会漂移，论文需固定模型快照并报告日期；
   建议使用本地开源 LLM（Qwen 等）复现一遍作为对照。
4. **人工评测成本**：MOS 昂贵，先用自动代理指标 + 小样本人工验证，再决定是否上大规模人评。
5. **先小后大**：先用 1 本书 + 1 张表证明指标有效，再扩展到基准数据集，避免一上来做"大而全"。
6. **声音克隆与隐私**：参考音频必须有明确授权、来源、用途范围和可撤回路径；论文与 demo 不应发布无授权声音，
   更不能把“模仿名人 / 真实人物”当作卖点。
7. **自动指标的边界**：speaker embedding 距离不等于人耳可分辨性，UTMOS/NISQA 不等于叙事质量；二者都必须以小规模、
   预注册任务设计的人类听测校验。
8. **一句话战略**：**把"能跑的系统"变成"能被度量的系统"，再把"能被度量的系统"变成"有主张的方法"，最后补一个 demo 保底。**

### 8.1 关键技术瓶颈与研究边界

- **隐式说话人归属仍难**：文学文本经常省略说话标签，判断依赖跨句/跨章代词、对话轮次和叙述视角。最新英文引语归属结果很强，但数据集、语言和任务定义有限；不能把英文基准准确率外推为中文有声书质量。[2026 引语归属预印本](https://arxiv.org/abs/2608.02359)
- **长篇人物链接会累积错误**：别名、敬称、亲属称谓、重名和视角变化都可能造成错合并或漏合并；一次错误写入全书记忆后会影响许多段落。已有工作展示了动态人物记忆路线，但“有记忆”不等于记忆永远正确。[COLING 2025 LlmLink](https://aclanthology.org/2025.coling-main.751/)
- **证据真实性与证据充分性是两种指标**：区间校验能保证证据文字确实来自原文；还需要标注者判断该 span 是否真的支持“此段由该人物说出”。应分别报告 evidence span grounding precision 与 evidence sufficiency，而不能把引用了原文等同于解释正确。
- **置信度容易失准**：LLM 自评不能直接解释成真实概率；不同小说、体裁、年代和标点规范都会造成分布偏移。一般性的 conformal abstention 可作为“低把握就弃答/送审”的方法参考，但不是文学角色归属的现成保证；必须检验校准与测试分布假设。[Conformal Abstention 预印本](https://arxiv.org/abs/2405.01563)
- **人物声音固定不等于合成表现完全一致**：固定 voice ID/参考音频解决身份映射，但文本、情绪控制和 API 版本仍可能改变韵律、音色观感或发音。身份一致性、情绪适配和自然度要分开测量。
- **中文场景评测仍不足**：ACL 2026 已出现含中文的虚构文本共指资源，说明中文数据基础在进展；但它不是与项目目标直接匹配的“中文小说引语归属 + 证据标注 + 多角色成品听测”一体基准。[GOLEMcoref（ACL 2026）](https://aclanthology.org/2026.acl-short.39/)

### 8.2 项目定位：应用系统与研究项目并行

**产品定位**：这是面向读者、创作者和出版流程的落地应用。它解决长篇有声化中的实际痛点：人物难跟踪、同一角色跨章换声、中文专名读错、整书人工校对成本高。用户价值应以人物辨识/理解、每千字校对时间、返工率、合成成本和离线可用性验证，而不是只展示 UI 或引擎数量。

**研究定位**：仅把 TTS Provider、角色表或播放器接起来属于工程集成；有发表潜力的研究主张应聚焦方法和证据，例如：“原文对齐证据 + 全书实体记忆 + 校准置信门控 + 风险驱动人工复核，能否以更少人工审阅降低中文长篇多角色有声书的身份错误，并维持跨章声音一致？”至少需要公开标注协议、按书划分的测试集、强基线/消融和人工听测。

**建议的阶段性成果**：

1. 近期先把源 span、稳定 `entity_id`、别名状态、证据类型与人工确认写入 V2/sidecar，并保留 V1 迁移与回退。
2. 同步制作小规模中文小说金标准集；先验证证据质量与置信度校准，再决定是否自动接受任何阈值以上的角色判断。
3. 对比“逐章独立判断 vs. 全书人物记忆 vs. 证据约束 + 风险审阅”，报告身份正确率、别名 F1、证据充分率、审阅预算下错误召回和跨章听众混淆率。
4. 将完整交互闭环作为 System Demo/应用成果；只有在对照实验显示稳定增益后，再把它作为 NLP/语音论文的核心方法贡献。
