# MiMo 角色音色设计接入方案

核实日期：2026-10-16。本文为后续实现设计，尚未接入 VoiceDesign／VoiceClone，也未为本方案调用在线合成。既有九章先导保留为预置声音基线，人工结果和角色设定不改。

## 能力与当前实现

小米官方文档区分三个模型：

| 模型 | 输入声音条件 | 本项目当前状态 |
|---|---|---|
| `mimo-v2.5-tts` | 预置 voice，加自然语言表演指令 | 已使用 |
| `mimo-v2.5-tts-voicedesign` | 自然语言声音描述 | 待接入 |
| `mimo-v2.5-tts-voiceclone` | 参考音频，加自然语言表演指令 | 待接入 |

VoiceDesign 的声音描述放在 `messages` 的 user 消息，原文放在 assistant 消息；audio 不传 Mia／Chloe 等预置 voice。为保持书籍原文，显式使用 `optimize_text_preview=false`。声音设计和克隆首轮均用非流式 WAV，避免将兼容流式接口误当低延迟流式。

当前 provider 的模型目录只列出 `mimo-v2.5-tts`，统一核心请求也检查预置声音目录；普通合成还有针对该模型名称的分支。因此不能只修改 model_name 或给 Mia 加一句角色描述，就宣称音色设计已接入。

- [MiMo 语音合成文档：模型、声音设计、克隆与请求示例](https://mimo.mi.com/docs/en-US/quick-start/usage-guide/audio/speech-synthesis-v2.5)

## 建议生成流程

1. LLM 从原文产生角色剧本：保留正文，识别说话人，合并别名并保持全书角色 ID；不擅自改写书籍，也不把未知年龄、性别等猜测当作原作事实。
2. 在角色层生成声音卡，记录持久的声区、共鸣、质感、发音习惯、口音和适用语言。全书复用同一份有版本号的声音卡；每句情绪另存，不随场景重写声音身份。
3. 联合检查角色集合。高频对话的邻接角色优先在声区、质感或共鸣上形成可听差异；保持原角色设定，避免只靠提高音量、极端快慢或夸张情绪区分。
4. 用 VoiceDesign 合成共同短文本，测量角色间差异及同描述重复请求的变化，同时检查文字完整性。描述不同不能直接作为实际声音不同的证据，仍需机器检查与人工试听。
5. 保存通过检查的候选音频、准确转写、原始响应和声音卡。先验证“固定描述直接生成”的稳定性；若漂移明显，再试验“设计参考音频后，固定参考用 VoiceClone 生成正文”。后者是待实测的工程方案，不能预先承诺绝对一致。
6. 角色声音确认后锁定，分段合成时复用身份条件，只改变当前句的表演指令。继续使用已有拼接、内容、信号与同角色一致性检查；单段修复不悄悄换角色声音。

示例仅说明描述差异，不代表修改 Alex／Blair／Casey 的已确认设定：

| 声音卡示例 | 可听目标 |
|---|---|
| A：低中声区，胸腔共鸣明显，略有颗粒感，吐字清楚 | 沉稳、有厚度 |
| B：中高声区，明亮集中，质感干净，辅音清楚 | 明亮、利落 |
| C：中声区，温润圆滑，轻微气声，句尾自然收束 | 柔和、松弛 |

英语和中文分别核验；英语优先。采用同一描述或参考音频，也不能直接推定跨语言音色稳定。

## 工程改动位置

- 角色资料：增加声音身份描述、候选／锚点 ID、语言、版本与确认状态；与句级 tone 分开。默认 LLM 生成流程目前主要提供人物名称、性别和通用朗读指令，还需扩展输出与校验。
- MiMo provider：显式支持预置／设计／克隆模式，按模型构造 audio；设计模式必填描述，克隆模式读取参考文件而非预置音色名。主链与统一核心使用同一请求构造，避免行为分叉。
- 请求缓存：纳入实际模型、完整描述、精确正文、参考音频内容哈希及真实输出参数。声音卡、参考音频变化时，相关角色音频及质量报告失效重建。
- 声音库与选角：以经过探针核验的设计声音 ID 作为候选，现有互动图算法继续比较实际声音，角色适配与互相可辨识分别检查。
- 响度：新声音重新测量，不沿用本轮 Mia 0 dB／Chloe -5 dB。所有比较组使用相同处理协议。
- 质量记录：区分机器提示、人工确认和未知；未完成内容核验的样本不作为角色锚点。保留旧实验，另存新一轮材料。

## 最小验证顺序

第一步用现有三个角色各一份声音卡，朗读两条共同英文短文本，共6次设计请求；先确认接口可用、文字完整、基本角色差异及跨文本稳定性。固定执行顺序和请求上限，不自动扩展候选或重试。

随后每个角色对其中一条文本再独立请求一次，增加3次，专门检查同条件随机变化。重复结果按预定检查规则保留，不只挑最好的一次。当前没有实际运行这些请求。

如有必要，再用各角色已核验的设计参考，生成新的共同正文，对比直接设计与固定参考克隆；这是独立后续阶段。每个请求均可观测，参考缺陷不能带入整章。

角色差异、同角色稳定性、内容完整性、接缝和响度分别报告。声纹距离只作筛查，最终辨识收益需要独立听众。小规模先导不估计泛化能力或论文显著性。

## 与论文问题的关系

“LLM 写声音提示词”是系统功能，本身不能据此声称创新。可检验的研究问题是：在角色属性适配约束下，利用互动关系联合设计与筛选声音，是否比逐角色独立描述更容易辨识，同时保持跨段一致性和内容完整性。

对照可比较预置音色、独立角色描述、互动约束描述；描述相关对照保持同一模型、候选生成和筛选预算。设计＋克隆另做稳定性消融，不把后端变化带来的改善全部归于互动图方法。已有质量评估与局部修复继续作为合成后的保障模块。
