# 网页常规入口与后台环境验证

2026-10-17。仅修复工程启动流程，不开展论文实验、其他引擎适配或真实模型合成。

问题复现：系统 Python 3.13 运行 `python3 main_ui.py --help`，在导入 OpenAI 客户端时因缺少 `distro` 退出。此前本地页面由音频质量环境直接调用 `host_ui` 启动，这不能证明日常入口可以启动。

实现：

- `main_ui.py` 的真正入口使用 `utils/project_runtime.py`，优先选择本项目已存在且有可执行解释器的 `venv_audio_quality/`，没有时回退 `venv_chatterbox/`。已激活的虚拟环境或与当前解释器匹配的 Conda 环境优先保留；依赖不自动安装。
- CLI 开启统一质检时优先质量环境，显式选择已有本地引擎时沿用其环境；没有合适环境时保留当前解释器。未增加引擎适配。
- 仅 `__main__` 切换解释器，导入 `main`／`main_ui` 和 spawn 的 `__mp_main__` 均不切换。以 `sys.prefix` 判断已有虚拟环境，避免 `python`／`python3` 符号链接误判造成重启。
- 保留用户设置的模型缓存与镜像变量，默认缓存归选定环境管理。

证据：

- 修复后同一 `python3 main_ui.py --help` 退出码0，见 [启动帮助](startup_help.log)。环境为现有 Python 3.11.17、Gradio 5.50.0；未升级依赖。
- 从系统 Python 发起的真实 spawn 检查，父子均使用项目质量环境，子进程导入两个入口后解释器未变化，见 [运行身份](runtime.json)。没有启动合成或模型推理。
- 通过常规入口 `python3 main_ui.py --host 127.0.0.1 --port 7862` 启动本地服务，已核对端口进程监听127.0.0.1:7862。未为此读取被浏览器策略禁止的页面内容。
- 5项启动回归覆盖选择优先级、显式环境、缺失／损坏环境、参数与自定义缓存传递、导入及spawn不切换。完整633项中603通过、30按环境跳过，无失败错误，见 [回归日志](unittest.log)。沙箱外离线运行，不发送书籍正文或调用API。

验证边界：环境和生成后台的启动身份得到验证；本轮没有新书拆分或TTS生成，也没有新增浏览器视觉或听感验收。章节选择轮次的浏览器访问限制仍保留。
