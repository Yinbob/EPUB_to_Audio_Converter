# DeepSeek 拆分停止与时限修复（2026-10-19）

## 问题及调查边界

用户报告一次拆分运行八分钟仍调用，要求增加停止按钮。旧服务日志可见连续多章拆分与缺失 text_kind／精确覆盖校验失败引起的重试，但缺乏本次任务完整时间线，不能断言八分钟全部由某一个请求或某次重试造成。

原链路为人物索引→逐章叙述视角分析→逐块拆分，每块校验最多尝试两次；SDK max_retries=0 原已配置。单次同步网络 timeout=120 不是整个任务上限，也不是完整响应的绝对墙钟上限。关闭前端反馈不结束后台工作线程，原界面没有取消入口。

## 实现

- 新 SplitControl 仅作用于 WebUI 拆分的 ContextVar 作用域；人物索引、叙述分析、分块拆分统一使用可取消 AsyncOpenAI 请求，其他同步入口不变。
- 单次请求绝对120秒，SDK零自动重试；任务总上限30分钟。后台控制检查与网络异步取消越过普通异常重试／回退，不会在用户取消后继续章节调用。
- 停止按可信 Gradio Request.session_hash 定位，使用独立队列，取消三个入口的排队／反馈事件；不依赖用户当前是否仍选同一书籍。
- 停止与保存共用操作锁；取消先发生不写结果。等待任务真正结束才恢复生成按钮。
- 完成与停止竞态使用有界32项会话结果缓存：如果保存已提交，等待完成并回送13项完整结果，不误报取消或丢失角色表。
- 进度显示当前章节、块号、尝试次数、累计请求次数及单次上限。
