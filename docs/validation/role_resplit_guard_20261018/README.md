# 重新拆分与角色确认的状态保护

2026-10-18。继续 MiMo 网页工作流整合，未开展论文实验或新引擎适配。

## 问题及实现

原来的等待首帧只清除页面确认状态，服务端仍保留旧确认。生成准备摘要可凭旧记录重新启用“开始生成”；直接提交带有旧确认签名的事件也可能启动旧剧本。仅在拆分保存后清除服务端记录，不能覆盖模型等待期间；拆分失败时旧文件未变，也不能只靠内容指纹判定已重新确认。

现在按上传书籍指纹占用对应项目，在首帧等待反馈之前清除旧服务端确认，登记“正在拆分”和“需要重新确认”。正在拆分时拒绝启动合成、确认和保存归属；失败后保留原剧本文件，但旧确认仍不能直接启动，需重新确认。不同书籍的占用记录分别保存。

确认保存、叙述／逐段归属保存以及生成启动使用同一可重入操作锁，与拆分入口的占用登记互斥。它覆盖本地校验到保存／启动的完整操作，远端模型请求期间不持锁。若合成先启动，随后拆分会提示等待合成结束或停止，避免两条工作流穿插修改同一项目。

关闭反馈流不解除仍在工作的线程占用；只有实际完成或失败才释放。尚未启动线程时关闭则直接释放占用。原有同步入口与界面输入输出数量保持兼容；没有修改 CSS、布局、动态效果或语音模型。

## 验证

- [聚焦日志](focus.log)：53 项通过。包括旧确认／旧签名不能启动合成、失败后需要重新确认、关闭反馈后保持占用、失败可重试及界面准备状态。
- 新增确定性线程屏障检查：确认暂停在保存点、生成暂停在启动点时，另一线程尝试重新拆分，不能穿插；保存先提交则新拆分作废该确认，合成先启动则重新拆分被拒绝。
- [完整回归日志](full.log)：674 项，644 通过、30 按环境跳过。首次完整回归发现旧 VoxCPM 参数隔离测试未提供新增装饰器依赖，补齐测试夹具后全量重跑通过；没有改动其模型适配。
- 独立 reviewer `split_feedback_finish` 首轮要求补齐原子操作边界，修正后将该项评为 resolved，最终 disposition 为 **ship**，限于所评分的源码／自动化并发行为。

所有模型和启动动作均使用离线替身，未向 DeepSeek／MiMo 发送新内容。浏览器仍受既有策略限制，没有重试或绕过；本轮无视觉、动效或真实语音质量验收。

本地网页服务在确认无生成子进程或活动请求连接后，按原地址重启加载修复。旧页面需要刷新，不能继续使用上一个服务的事件编号。项目总目标仍在推进，研究实验与后续引擎适配按用户要求暂缓。
