# DeepSeek 剧本拆分等待反馈修复

用户已确认章节和角色工作区的排版显示正常，但实际生成／拆分剧本时仍看不到等待提示。本次只修复该反馈链路，不调用真实 DeepSeek 或 TTS。

## 原因与实现

全局样式隐藏了 Gradio 的 `.wrap.translucent` 等原生等待提示。另查安装包前端源码，未确定百分比的 `Progress(None, desc=...)` 不会显示阶段文字。因此单纯继续发送 Progress 回调无法保证用户看到阶段。

- 改为始终位于拆分按钮附近的独立 HTML 状态区，沿用全站圆角、玻璃材质和深浅色令牌。
- 手动点击立即显示“正在准备剧本”，由本地脚本更新自有 HTML 子树，保留 Gradio/Svelte 组件锚点。
- 三个拆分入口均使用流式界面回调：先发送等待状态，再启动同步工作；人物索引、章节拆分等真实回调持续传到状态区。
- 等待动画为 CSS 线性旋转；每秒仅更新已等待时间。无新阶段时发送跳过更新的心跳，不反复重挂载动画，不虚构完成百分比。
- 开始时作废旧确认、禁用重新生成按钮；保存完成或失败后恢复操作并显示对应结果。拆分共享既有串行事件组。
- 同步拆分入口及原来的十项返回保持兼容；界面流式入口额外输出状态区和按钮，共十二项。

## 工程验证

- [聚焦检查日志](focus.log)：52 项通过。覆盖慢请求、心跳、失败恢复、自动拆分关闭和队列隔离等。
- [完整回归日志](full.log)：668 项，638 通过、30 按环境跳过。
- [实际 Gradio 输出检查](stream.log)：在完整回归后，将注册生成器检查增强为 `Blocks.process_api`，再次通过 1 项。使用会话状态及真实预处理／后处理，确认等待、阶段和完成三帧 HTML／按钮输出；首帧发出时替身工作尚未启动。
- [一次静态界面扫描](detector.json)：仅报告既有主转换进度条的 `transition: width`，与此次新增反馈无关。

独立 reviewer `split_feedback_finish` 的结论为 **ship**，严格限于源码及自动化行为范围。浏览器访问曾被策略拒绝，本次没有重试、绕过或新增截图；新等待动画的实际视觉、键盘／触屏操作及辅助技术播报尚未验证。用户此前“界面显示正常”的确认仅覆盖原有排版。
