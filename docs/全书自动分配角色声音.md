# 长篇书籍自动分配角色声音

入口：打开网页，开启「为旁白和人物使用不同声音」，先生成或载入当前书籍的 MiMo V2 剧本，再进入「2 · 角色声音 → 全书自动分配」。首版处理单本、单一中文或英文书籍。

## 使用顺序

1. 选择本书语言，点击「查看统计」。页面显示实际已分析／尚缺的章节数；只有人物名单的全书索引不算已完成段落分析。
2. 点击「分析全书／继续补齐」。只补齐缺少或与原文不匹配的章节，完成一章保存一章；这一步不扩大上方最终选择的生成范围。普通上传和单章试读不会触发这项全书任务。
3. 选择对应语言的已核验声音库，点击「生成／补齐声音方案」。页面显示库的实际可用数量；当前已有中文 3 种、英文 2 种，并不代表全部官方声音。导入区接受含已核验探针的 MiMo 声音库 JSON，不会自动付费建库。
4. 检查分配原因。描述声音可直接双击表格里的「声音描述」或「朗读要求」修改，其他列保持原样，然后点击「将方案应用到角色表」。应用前会再次检查来源、声音库和锁定设置。
5. 下方人物设置自动显示新配置。继续使用原来的「试听当前人物」「固定这次试听的音色」；人物锁定仍在现有高级工具中。最后进入「3 · 复核与确认」，确认后才通过原来的生成按钮合成。

生成方案只做文字分析和配置。真实声音是否合适、人物是否容易区分，需要单独试听。MiMo 的描述声音多次合成仍可能变化，满意的试听可固定为参考音并用克隆方式复用。

## 分配规则和例子

排名依据实际朗读字／词数，包括人物对白和第一人称自述。同一句拆成多段，不会增加它的朗读量。时间只是按中文 240 字／分钟、英文 150 词／分钟估算，不是测出的音频时长。

例如一个人物前九章很少说话，最后三章有大量自述，仍可能排在常驻人物前面；偶尔隔五章才说一句的人物显示较长缺席间隔，但不会仅凭间隔被指定用描述声音。网页最长缺席章数包含首次出场前和最后出场后的章节。

有实际朗读内容的独立旁白默认先预留一个合适的内置声音；人物自述计入该人物，不计入独立旁白。没有实际内容的旁白不占名额。随后按朗读量顺序，尽量为人物安排合适且不重复的内置声音。目录已知的语言、性别及导入库的完整人工适配表共同排除明显不合适的声音；未知属性不猜测。剩余声音不适合某人时，该人用描述声音，内置声音仍可分给后面的适合人物。

已有探针特征用于降低经常对话人物之间的声音相似程度；同分时优先选择整体差异更大的组合。这只是声音特征的比较，不能当作真实听众辨识率。用户已锁定的 preset／design／clone 配置保留，包括明确锁定的共享声音和不在本次库中的既有内置声音。

## 保存、停止和重新计算

全书分析及草案保存在输出根目录 `.role_casting/<书籍指纹>/`，正式应用前不会覆盖 `.role_projects/` 的原剧本。分析正文、解析设置、归属和人物一致时复用章节；只调声音或锁定声音会保留全书分析，并撤回旧声音草案。修改归属、合并人物或更改来源后需要重新计算方案。

DeepSeek 每批最多生成 8 位人物的描述，成功批次逐人保存。描述包含固定声音特点及可选朗读要求，应用后有独立版本；场景情绪不当作人物永久音色。输入包含人物信息、代表性原文和对话对象，不把未知年龄或性别编成书中事实。有效的人工修改描述同样复用。

单次请求最多 120 秒，单次全书任务最多 30 分钟。点击「停止本次分析／描述」或请求失败后，完成章节及成功批次保留；再次操作只补缺失或失效项，不自动重试失败请求。停止按钮只控制本网页会话启动的全书任务，即使已换书仍可停止旧任务。

草案可以使用机器提出的归属统计，但未知归属单独列出。自动选声和应用都不把 `proposed`、`unknown`、`needs_review` 改成人工确认。归属核对继续沿用现有入口。

## 主要实现

- `audio_core/hybrid_casting.py`：显式草案归属模式、字／词数统计、旁白预留、适配约束、声音卡校验；命令行默认仍要求已确认归属。
- `audio_core/casting.py`：保留锁定和自动不复用，互动差异优先，整体差异作为同分依据。
- `ui/book_casting.py`：核对实际章节和正文覆盖，逐章原子保存，描述分批缓存，来源指纹与旧方案拦截。
- `ui/book_casting_ui.py`：独立网页组件及控制流程，复用现有任务时限、停止、项目互斥与等待反馈。
- `ui/web_ui.py`：在角色声音页装配，应用后更新人物设置并撤回生成确认。角色剧本不增加必填字段，正式合成仍走原入口。
