# 有声书统一核心与质量评估实施方案

日期：2026-10-15。本文保留最初研究设计。2026-10-16 起的实现与验收状态见 [MiMo 统一核心使用与验收](MiMo统一核心使用与验收.md)：首轮只支持 MiMo，不做 MiniMax 适配，不加入计费逻辑；未来适配本地 Qwen TTS／VoxCPM。正文的拟议文件名、MiniMax 对照和费用配置均属早期设计，不能直接当作已实现入口或已完成实验。

## 2026-10-16 新增约束：中英双语，英语优先

用户确认现有中文共同探针核验无问题，并明确要求项目同时支持中英两种语言，英语优先。下文早期“中文有声书”范围据此扩展；首轮引擎仍仅 MiMo，后续为本地 Qwen TTS／VoxCPM。

具体实施采用同一管线、分别计量和验收：英语内容按词对齐（WER）、中文按字对齐（CER），英语保留词界及否定词；英语语速使用词／分钟，中文使用字／秒，中英混读不直接套单语言阈值。英文数字、日期、缩写不自动改成中文读法；明确读法可用词典登记，尚未确定的数字或缩略词等价读法保留复核。分块保护英文单词、缩写和小数，内容修复使用英文指令。

声音探针按语言分组，中文核验不能代替英文核验。新的选角工具默认目标为英语，使用声音库前检查语言范围。当前中文 12 条探针及 3 组一致性已人工通过并建库；英文新增 6 条共同探针，其中 E06 自动提示疑似额外朗读，均尚未人工核验。不能把英文工程链路可用写成英语质量已验收。

后续顺序：先完成英文探针试听和内容问题定位，再扩展英文数字／日期／缩略词专项与更多独立书籍；中文保留回归样本。边界模型按语言报告召回和误报，按来源分训练／开发／测试；英文疑似多读不直接填成断音等边界标签。听众选角实验分别报告英语和中文结果，英语先做。100ms、50%→100% 起读策略继续限定于已确认的原接缝，不自动推广到全部英语边界。

### 英文内容比较的实现进展（v17）

英文内容核验新增有限数字／日期等价规则，发送给 TTS 的英文正文不变：支持明确基数词、小数、百分数、序数及有效英文完整月份日期。歧义编号、版本、独立年份、斜线日期、非法日期和缩略词继续保留复核；转换事件与版本写入报告，比较坐标与原文来源坐标分开。先完成规则反例和受限修复调度检查，再复用既有中英音频回归；数字专项真实合成、独立人工验收尚未开展。具体边界及结果见 [v17 工程记录](validation/audio_core_20261016/english_reading_equivalence_v17.json)。

## 1. 目标与优先级

目标：在底层 TTS 模型不可修改、预算有限的条件下，生成内容准确、衔接自然、角色稳定且容易辨识的中文有声书，并定位问题、控制返工成本。

用户指定的检测优先级：

1. 拼接质量：断音、漏音、异常重叠、突兀停顿。
2. 同一角色的音色、音高、语速一致性。
3. 重复、漏读及其他内容错误。
4. 削波、噪声、响度、其他听感问题。

这是开发与检查资源的排序，不代表严重漏读可以被较好的拼接分数抵消。最终报告同时保存缺陷严重程度与检测置信度。

| 能力 | 在统一核心中的位置 | 第一版实现 |
|---|---|---|
| 中文朗读规范化与停顿建模 | 合成前预防 | 确定性规则、变换记录、结构化停顿 |
| 跨块一致性 | 合成、边界处理与质检 | 可追踪分块、角色锚点、安全组装 |
| 客观质量评估 | 共用观测层 | 块级、边界级、角色级、章节级报告 |
| 黑盒 TTS 成本受限修复 | 反馈控制层 | 规则动作表、请求记账、预算截断 |
| 听众辨识自动选角 | 合成前角色声音分配 | 小声音库、互动图、带锁约束优化 |
| 边界小模型 | 质量评估的重点方法 | 特征分类器起步，再比较小型 CNN/CRNN |

## 2. 已核对的现有代码与缺口

以下路径均相对项目根目录。

| 现有位置 | 可复用能力 | 必须处理的缺口 |
|---|---|---|
| `role_script/models.py` | SourceSpan、角色实体、VoiceProfile、SynthesisUnit、AudioArtifact | SynthesisUnit 尚未携带完整原文定位、朗读变换、内部块信息 |
| `role_script/planner.py` | 剧本验证后生成计划、角色参数和停顿 | 增加普通模式适配及朗读中间表示；避免改变原文验证语义 |
| `role_script/project_store.py` | 人物项目原子持久化 | 不是音频产物和请求账本，不应承担所有持久化职责 |
| `role_script/audio_quality.py` | 语速、削波、静音、ASR-CER、二次候选比较 | 缺少边界、声纹、局部定位；现有阈值需校准 |
| `role_script/audio_pipeline.py` | 解码、MiMo 本地变速、静音插入、编码与顺序组装 | 需要导出样本级时间映射，并在最终处理后检查边界 |
| `core/audiobook_generator.py` | 角色段质检、MiMo 质量重试 | 普通模式未统一接入；临时目录最终会删除；先组装再补最终质检 |
| `tts_providers/openai_tts_provider.py` | MiMo 段合成、缓存、实际请求参数 | 内部分块后直接合并，整段异常会重跑；同参重试会命中缓存 |
| `tts_providers/minimax_tts_provider.py` | MiniMax 段合成、缓存、WebSocket | 同样存在内部分块、段级重试与临时缓存；语速在远端应用 |
| `tts_providers/segment_synthesis.py` | 请求配置指纹、原子写文件 | 扩展为原始请求产物与后处理产物两层索引 |
| `utils/voxcpm_asr.py` | SenseVoice CPU 懒加载转写 | 当前返回纯文本，不能直接提供字级时间位置 |
| `role_script/normalization.py` | 剧本文本覆盖率规范化 | 与朗读规范化职责不同，不能直接替换 |

重要区别：MiMo 当前角色链路的 speed 由本地音频处理实现；MiniMax 的 speed 进入实际请求。改变 MiMo speed 不应自动产生新的远端合成；改变 MiniMax 请求 speed 则可能需要重新调用。

## 3. 统一执行链与数据契约

```text
章节原文与原文坐标
  → 角色脚本验证／普通模式旁白适配
  → 朗读规范化与分块计划
  → 自动选角与角色声音锁定
  → 请求级预算预留 → TTS 原始块 → 持久化
  → 块级质检 → 局部组装 → 边界及一致性质检
  → 选择修复动作 → 仅重算受影响区域 → 重新质检
  → 最终编码与复检 → 音频、问题清单、成本和实验报告
```

### 3.1 数据对象

保留现有剧本格式作为上游输入，新增独立的、可版本化的朗读计划。所有跨 spawn 的数据对象只包含可 pickle 的纯数据，不放 Provider、模型、数据库连接、文件句柄或 Gradio 对象。

| 对象 | 必要字段 |
|---|---|
| ReadingUnit | unit_id、segment_id、source_spans、source_text、tts_text、spoken_reference、normalization_edits、entity_id、profile_id、tone、chunk_ids |
| TextEdit | 原文区间、朗读文本区间、变换类型、规则版本、原值、新值、是否人工确认 |
| ChunkPlan | chunk_id、unit_id、tts_text 区间、原文映射、顺序、请求配置指纹、边界类型 |
| BoundaryPlan | boundary_id、left_chunk_id、right_chunk_id、same_speaker、boundary_kind、停顿策略 |
| RenderSpan | artifact_id、start_sample、end_sample、变速／裁切／重叠操作及其参数 |
| QualityIssue | issue_type、severity、scope、关联块／边界／角色、时间区间、原文区间、证据、confidence_kind、置信度或空值 |
| QualityReport | scope、问题列表、各维度状态、模型与规则版本、未完成项目、总体状态 |
| RepairAttempt | 输入产物、动作、实际请求、前后报告、预算变化、选中／拒绝原因 |

`source_text` 不原地修改，原文坐标基于解析后的规范章节文本；`tts_text` 是实际请求内容；`spoken_reference` 是核验用的可接受朗读形式。数字等价转换是比较规则，不能把模型自己生成的错误读法自动认证为标准答案。

普通模式以单一旁白角色建立同样计划。第一版普通模式只接通 MiMo/MiniMax 新链路；其他引擎保持现有能力并明确显示未覆盖的质量维度。

### 3.2 样本级组装记录

- 中间音频解码为统一采样率的 PCM。评估副本可转换成 16 kHz 单声道，但不能因此强制降低最终输出质量。
- 边界位置来自解码后的实际样本数，不根据字符数估算。
- 插入停顿、变速、裁切、淡入淡出都产生新的 RenderSpan，不能只改音频而不更新时间表。
- 检查数量、顺序、是否重复引用／遗漏 chunk_id、PCM 长度是否符合操作计划；不能把不同操作后不再相等的波形直接要求逐样本一致。
- 最终 MP3 等有损编码可能带来延迟或填充，应使用容差与内容对齐复检；样本数严格检查在 PCM 阶段完成。
- 第一版只对已知组装边界做重点检查；段内未知异常需滑窗或 ASR 补充，不能宣称已覆盖所有时间位置。

### 3.3 持久化与版本

建议目录结构（尚未创建）：

```text
<output>/.audio_projects/<book_sha256>/
  reading_plan.json
  casting.json
  project.sqlite
  raw/<request_fingerprint>/<sample_id>.<actual_format>
  rendered/<render_fingerprint>.wav
  reports/<run_id>/
  models/<model_version>/
```

- `raw` 保存实际 Provider 响应，不覆盖历史候选；`rendered` 保存本地处理结果；临时目录只放可重建文件。
- SQLite 表建议为 runs、artifacts、requests、reservations、issues、repair_attempts、model_versions。第一版 worker_count=1，事务内预留预算；增加并发时再使用单一调度器协调。
- 请求指纹包含引擎、实际模型、实际文本、有效音色与指令、请求输出参数及适配器版本；本地 MiMo 变速进入 render 指纹。
- `reuse` 复用既有样本；`resample` 生成新的 sample_id 并绕过样本命中。模型不支持 seed 时仍可请求新样本，但不承诺其与上次不同。
- 报告键包含音频内容指纹、文本参考版本、角色锚点版本、质量模型版本，避免变更之后复用旧分数。
- 实验中的既有缓存仍保留原始逻辑生成成本，不能因为缓存命中就将某方法的实验成本记为零；同时单独记录本次实际支出。

## 4. 模块 A：朗读规范化与停顿

### 4.1 第一版规则

只自动处理上下文明确、能回溯的变换：年份、完整日期、百分数、带单位的小数与用户指定词典。订单号、版本号、电话号码、专名等歧义项目保持原样并可标记复核。

例：`2026年增长3.5%` → `二零二六年增长百分之三点五`；每个转换都保留原文映射。识别结果 `3.5%` 与 `百分之三点五` 可以通过等价规则比较。

多音字首版做词组词典与问题提示。只有适配器已证实支持读音控制时，才使用相应语法；不能把未经支持的拼音、SSML 或私有停顿标签直接塞进正文。

### 4.2 分块与停顿

- 按句子及段落规划，首轮试验可从每块 150～400 个汉字的配置范围探索；这是试验参数，不是所有引擎的最佳长度。
- 普通模式尽量在完整句边界分块；角色模式不跨角色合块。短块只在同角色、同场景且原文顺序连续时考虑合并。
- 确保规划块不再触发 Provider 内部的隐藏分块；如果仍需内部切分，必须把所有子块和请求暴露到统一记录中。
- 停顿用结构化字段表示。目标是合理的总间隔，应考虑原音频自带尾静音与首静音，避免重复插入导致拖沓。
- 第一版只在安全低能量区域处理停顿，不主动剪掉有效语音。无法确定时保持原样并报疑似问题。
- 固定毫秒值仅是可调整初始配置，不能将所有句号、逗号或换人统一规定为唯一正确时长。

验收：原文映射可回溯，歧义样例不被擅自改写，所有块按顺序覆盖预期朗读内容，没有未知控制符流入 TTS。

## 5. 模块 B：质量评估与边界小模型

### 5.1 检查顺序

1. 文件／结构完整性：空音频、缺块、错序、重复引用、解码失败。
2. 所有已知边界：低成本声学检查与边界模型。
3. 同角色连续性：参考音色、近期已通过片段、音高与语速统计。
4. 内容完整性：分块及跨边界 ASR 对齐。
5. 噪声、削波、响度与可选听感分数。

实验模式对测试样本运行完整检查以保证可比性。产品省算力模式可优先运行疑似区域的 ASR，但必须标记其他内容为未评估，不能判定整章内容完整。

### 5.2 边界检测器 v0：先做可解释基线

输入分两种尺度：边界附近短窗口用于爆点、断续等声学问题；更长的左右语音及文本用于句尾截断、重叠等判断。初始可取前后各 2 秒，后续由验证集选择窗口。

特征包括：

- 波形跳变与局部能量，频谱／谱通量变化；
- 边界前后语音活动、首尾静音及计划停顿；
- 有声帧上的音高统计及缺失标记；
- 边界类型、是否同角色、是否同场景；
- ASR 的跨块重复／缺失证据（可选，不能作为总能获得的输入）。

从逻辑回归或小型 MLP 开始，多标签预测 `click`、`cutoff_suspected`、`overlap`、`unexpected_gap` 等。只有数据充分时增加独立的时间定位头；第一版优先定位到已知边界，不承诺精确到音素。

### 5.3 边界检测器 v1：可实现的神经网络候选

这是待比较的起始结构，不是已有模型或效果保证：

```text
16 kHz 评估副本
 → 80 维 log-Mel（约 25 ms 窗、10 ms 步长）
 → 3 个小型二维卷积块（通道 16 / 32 / 64，频率方向池化）
 → 保留时间序列，拼接“距边界位置”通道
 → 单层双向 GRU（每方向 64）
 → 左／右窗口分别池化并拼接
 → 拼接边界类型、同角色标记、声学统计及缺失掩码
 → 64 维 MLP → 多标签 sigmoid 输出
```

- 用多标签 BCE；类别权重由训练集确定。先与特征基线比较，不因用了神经网络就默认更优。
- 学习率、早停和窗口长度只使用开发集选择；冻结测试集后不反复按测试错误调参。
- 百万参数以内是该检测头的规模设计目标，需以实际统计为准；不包含 ASR 和声纹模型。
- 将概率在开发集校准；未校准时 confidence_kind 明确写 uncalibrated。置信度不足返回待复核。
- VAD 只用于判断语音活动，不能单独证明吞字。强制对齐也不能单独证明文字真的读全，必须结合自由转写及人工抽查。

可复现的首轮训练配置：AdamW，学习率 0.001，weight_decay=0.0001，batch_size=32，最多 50 个 epoch，开发集损失连续 8 个 epoch 不改善则早停，分别使用 3 个固定随机种子。它们是待验证的起始超参数；类别过少时只训练特征基线，不强行训练多标签网络。保存最佳开发集检查点、划分清单、特征归一化参数及类别计数，模型选择不能使用测试结果。

### 5.4 音色、音高与语速一致性

- 音色采用预训练声纹向量，首先比较该角色稳定参考与近期通过样本。角色锚点只由通过核验的音频更新，不能无条件滚动平均所有输出。
- 短语音证据不足时不输出强结论；可累计同角色的多个短片段。
- 音高只在有效有声帧统计，以中位数、范围、趋势为主；考虑声调、句型和 tone，不惩罚所有音高变化。
- 语速同时报告“含停顿整体速度”和“排除静音的发音速度”，参考规范化后朗读单位而非简单原文汉字数。
- 角色切换处不要求音色一致；角色内一致性也不等于不同角色之间容易辨识。
- 最终变速后再计算一致性与选角相关特征，避免用原始音频特征代表最终听到的声音。

### 5.5 重复与漏读

- 复用 SenseVoice CPU 转写；转写缓存基于音频内容与模型配置。
- 文字比较先统一数字、单位等可接受等价形式；保留编辑操作类型，而非只输出一个 CER。
- 对左右末句／首句的联合窗口做跨边界核验；同时检查组装清单，发现整块重复或遗漏。
- 对时间定位，第一版报告块／边界级位置；后续增加经验证的时间戳或对齐适配器。
- ASR 失败、低可信专名或多音字问题进入 incomplete／needs_review，不自动当作已确认漏读。

### 5.6 输出与候选选择

四维分别输出 stitching、consistency、content、signal。每维支持 passed / failed / incomplete；问题另有 confirmed / suspected。

保留已确认的严重完整性缺陷作为不通过条件，其余候选依次比较拼接问题、一致性问题、内容问题及信号问题。疑似问题不直接等价为已确认缺陷，严重内容错误也不能通过其他维度平均分抵消。

报告应能回答：发生在哪里、证据是什么、是否已确认、哪个检查未完成、建议什么动作。UI 总分只作辅助展示。

## 6. 模块 C：跨块组装与连续性控制

第一版对 MiMo/MiniMax 采用引擎无关方法：固定角色声音配置、句边界分块、停顿规划、保守边界处理、合成后检测与修复。

- 不在所有边界默认 crossfade。存在有效语音时，重叠可能损伤字音；只在已确认安全区域尝试极短淡化，并比较处理前后质量。
- 一旦字音已丢失，淡化不能恢复内容；应重新合成受影响块。
- 两个单块都通过但组合失败时，先检查组装操作，再决定是否重新切分或重合成；不要无条件重跑整章。
- 修复一块后，重新计算该块与左右边界、角色局部统计和下游最终文件；无需重评不受影响的整本音频。

VoxCPM 上下文续接作为后续可选后端：验证安装版本与模型接口后，使用通过核验的同角色短句及准确对应文本作为上下文；固定角色参考作为音色锚点。不能把前一个其他角色的声音当成续接上下文。

续接依赖形成有向图。父块更换时标记依赖块过期；异常上下文不再传播。不得根据未经核实的假设按固定时长裁掉输出开头。上下文收益需同时比较重复漏读、漂移、耗时与串行代价。

## 7. 模块 D：预算受限修复

### 7.1 第一版受限动作表

| 证据／问题 | 优先动作 | 远端成本 | 复检范围 |
|---|---|---|---|
| 清单错序、重复引用、遗漏已存在块 | 修正组装清单 | 无 | 结构与受影响边界 |
| 安全静音区的间隔异常 | 调整停顿、重新组装 | 无 | 边界、时长、内容未损伤 |
| 有证据的边界爆点 | 尝试安全淡化；否则重合成 | 本地优先 | 局部边界与内容 |
| 音频本身截断、确认漏读 | 同声音重采样；或改切分后重合成 | 有 | 内容及左右边界 |
| MiMo 语速偏快 | 小幅本地 atempo | 无远端调用 | 内容、语速、听感、声纹 |
| MiniMax 语速偏快 | 先比较本地处理；必要时调整请求 speed | 视动作而定 | 同上 |
| MiMo 内容反复出错 | 受限清晰朗读提示补丁 | 有 | 内容及一致性 |
| MiniMax 内容反复出错 | 同参新样本或重新分块 | 有 | 内容及一致性 |
| 同角色声音偏离 | 恢复锁定配置并重采样 | 有 | 角色一致性、边界与内容 |
| 证据不足、预算耗尽 | 保留较优候选并标记复核 | 无新调用 | 输出完整未解决清单 |

不默认调用额外文本 LLM 选择动作；现有 DeepSeek 反馈可保留为实验分支，其请求与费用也需计入。MiniMax 当前适配器不发送 tone，不能把增加 tone 当作已经可用的修复动作。

### 7.2 请求级预算

- 至少记录：实际请求数、输入字符数、生成音频时长、耗时、估算费用、可获取的服务端 usage，以及失败／超时状态。
- 不引用未经核实的价格。没有账单或 usage 时费用标为 estimated；超时且可能计费的请求标为 unknown，不能当作免费。
- 每次实际合成请求前事务预留预算，成功或失败后结算；不确定请求保守保留相应预算直到核对。
- 覆盖 Provider 内部重试，以及 SDK／传输层隐式重试。实验分支应关闭不可观测自动重试，或在传输层逐次记账。
- 全书基础预算、修复追加预算和声音探针预算分开；超出任何启用的硬上限均停止新增请求。
- 第一版每块最多 2 次远端质量修复，另有全局硬预算；网络重试不作为绕过硬预算的理由。局部处理也设动作次数上限，避免循环。
- 断点恢复按请求状态和产物恢复。没有服务端幂等保证时，不能把客户端 request_id 视为绝对防止重复计费的机制。

### 7.3 从规则调度到研究方法

v0：按照用户优先级，先选高严重度且证据充分的问题，优先本地动作。

v1：用开发集上的真实修复记录，估计“问题特征、动作、引擎”对应的修复成功率和成本。采用按重要性分层的选择：先处理拼接层，再一致性层等；层内按预计收益／成本排序，并始终保留严重内容错误约束。

本地零远端成本动作使用运行时间作为另一项代价，不能将零费用直接代入分母。估计不可靠时回退规则表，不做无预算约束的探索。

## 8. 模块 E：面向听众辨识的自动选角

### 8.1 声音探针库

首轮建议 MiMo 4 个、MiniMax 6 个可用声音，每个声音 4 条相同短文本，约 40 个逻辑合成样本；以运行前实际目录为准，不假设线上音色永久不变。

探针文本覆盖陈述、疑问、数字／专名、对白。先质检，再提取最终处理后的声纹、音高、语速、响度特征；不合格探针不能代表该声音正常能力。

首轮按引擎分别选角，固定模型、语速与主要风格。后续改变这些条件，应重验声音特征与角色辨识表现。

### 8.2 角色互动图与优化

- 节点是角色实体；同场景相邻对白频次形成边权，可增加多次交替说话的权重。
- 先使用人工确认的角色脚本，避免把说话人归属错误算成选角失败。
- 同一组探针文本上比较声音距离，跨文本汇总稳定性；声纹距离只是混淆风险代理，不能称为已经校准的听众混淆概率。
- 定义目标：互动边上的声音相近惩罚＋角色适配惩罚＋更改既有角色声音惩罚。对已锁定声音设置硬约束。
- 角色少时枚举带剪枝；规模扩大后使用贪心初始化与交换搜索，记录种子及目标值，不要求首版引入复杂优化依赖。
- 角色多于候选声音时允许低互动角色复用，并报告冲突；不能声称所有角色均可获得唯一音色。旁白是否独立作为可配置约束。
- 用户已经固定的声音与速度优先。性别、年龄、性格只作为可审查适配信息，不能在证据不足时转成硬约束。

### 8.3 与修复的边界

选角在正式合成前完成并锁定；单块修复不擅自替换角色音色。用户或选角算法改变角色声音后，对该角色相关音频及质检失效重建，不能只更新角色表而保留旧音频。

验证使用真实对话的角色辨识任务，同时报告角色适配偏好；仅提高声纹向量距离不能证明听众更容易辨认。

## 9. 文件拆分与接入顺序

建议新增共用包 `audiobook_generator/audio_core/`，避免继续把普通模式依赖塞入角色专用目录。以下均为待实现路径。

| 文件 | 核心职责／建议接口 |
|---|---|
| `models.py` | ReadingUnit、BoundaryPlan、RenderSpan、QualityIssue 等纯数据 |
| `reading.py` | `build_reading_plan(...)`、`normalize_reading_text(...)` |
| `store.py` | 原子产物写入、样本索引、运行记录与恢复 |
| `requests.py` | 实际请求事件、reuse/resample、隐式重试控制 |
| `budget.py` | `reserve(...)`、`settle(...)`、`remaining(...)` |
| `quality/boundary.py` | `evaluate_boundary(left, right, metadata)` |
| `quality/consistency.py` | 角色锚点、声纹、音高与语速比较 |
| `quality/content.py` | 转写缓存、等价文本比较、编辑操作及局部定位 |
| `quality/evaluator.py` | 统一状态与证据汇总，不隐藏未评估维度 |
| `join.py` | PCM 组装、时间映射、安全边界操作 |
| `repair.py` | `propose_actions(...)`、`select_action(...)`、局部失效重算 |
| `casting.py` | 探针特征、互动图、带锁声音分配 |
| `pipeline.py` | 共用执行链；普通／角色模式适配 |

现有 `role_script.audio_quality`、`audio_pipeline` 保留兼容门面并逐步转接，不一次性改写所有 Provider。通用计划不可抹掉 RoleScriptV2 的人物证据、用户锁定与原文验证。

Provider 优先新增可观测块级适配器，复用 `_request_mimo_chunk`、`_generate_audio` 等底层能力；通过兼容层保持旧 `synthesize_segment` 入口可用。统一质量模式下不能再由 Provider 静默合并未知子块。

WebUI 首版只增加：质量模式、未解决问题列表、按时间试听、修复预算、请求成本摘要与报告导出。依赖缺失时明确显示 incomplete，保持现有 UI 启动能力。详细开关置于高级配置，不让普通用户理解模型内部结构。

## 10. 首轮低成本实验

### 10.1 研究问题

- RQ1：边界位置、角色与文本证据能否在相同误报水平下提高真实拼接缺陷检出率？
- RQ2：相同修复预算下，分层调度是否比统一重试减少更多人工确认缺陷？
- RQ3：角色互动图分配是否比随机、属性匹配或全局声音分散分配提高听众辨识准确率？
- 辅助问题：规范化能否减少特定读法错误；安全组装是否改善边界而不增加内容损伤；上下文续接是否值得其额外代价。

### 10.2 先导样本与费用边界

- 准备 10 个连续场景，每场景 4 个待合成单位，共 40 个单位；覆盖单旁白续接、多人对白、数字读法和不同句型。
- 每个单位以 MiMo、MiniMax 各合成一次，约 80 个基线逻辑样本；每个单位长度限制为能完成单次请求。
- 独立声音探针约 40 个。两项合计约 120 个初始逻辑样本，不等于保证只有 120 次实际请求。
- 基线每引擎 10×3=30 个场景内边界，共约 60 个真实组装边界；这个规模只适合跑通流程及先导观察，不能包装成充分的模型泛化证据。
- 复用已有可追踪音频优先。人工扰动扩充不消耗 TTS 请求，但不能代替真实测试样本。
- 初始修复额度示例：基线 80 次请求对应最多 24 次追加请求，并同时限制追加字符量不超过基线计划的 30%；任一上限先到即停止。声音探针、网络失败和训练探索另行列账，不能挤入未说明的免费额度。
- 人民币预算依据运行前用户配置的价格和实际计费单位换算；不在方案中虚构当前价格。这里的额度是建议配置，不是已获具体付费执行授权。

### 10.3 数据构建与拆分

第一步人工核对真实音频的块与边界，标注类型、严重程度、位置和是否确定。然后从已确认正常音频生成截断、断续、重叠、重复、速度变化等扰动，补充训练。

先按书籍／场景／原始音频分组划分，再生成扰动。原音频及其所有变体必须留在同一划分。补充自然换人、情绪、自然停顿、短应答等困难负例。

正式研究再扩充独立真实边界与内容错误样本，覆盖更多书籍、声音与引擎条件；规模依据先导缺陷率、置信区间与所需比较精度决定。不能仅凭“300 条”就断言可以训练可靠模型。真实测试集不得完全由注入错误组成。

### 10.4 比较组

| 实验 | 比较组 | 固定条件 |
|---|---|---|
| 边界检测 | 声学规则；NISQA 不连续性基线；特征分类器；小网络；去角色／去边界信息消融 | 同一独立测试集、相同可用输入范围 |
| 一致性 | 全局固定阈值；角色锚点；角色锚点＋上下文条件 | 相同角色与最终音频 |
| 规范化 | 原文；确定性规范化；规范化＋停顿规划 | 共同人工朗读参考，记录额外成本 |
| 连续性 | 原始组装；安全停顿／边界操作；可选上下文续接 | 相同原文与声音；单独核验内容完整性 |
| 修复策略 | 不修复；预算内统一重试；规则策略；经验收益／成本策略 | 相同初始候选、动作集合、预算与独立终评 |
| 自动选角 | 随机；属性匹配；全局声音差异；角色互动图 | 人工确认角色脚本、固定质检与修复配置 |

不一次运行五因素全组合。先分模块消融，再选必要的交互实验，例如“有无自动选角×有无一致性修复”。

### 10.5 指标与分析

- 主要检测指标：真实断音／漏音分别召回率、每 100 个正常边界的误报、固定误报水平下召回、未能判断比例；同时报告精确率／PR 曲线，避免低缺陷率下准确率失真。
- 一致性：真实漂移检出、对正常情绪与换人的误报；声纹距离、音高统计只是辅助。
- 内容：人工确认的漏读／重复数量与严重程度，ASR 自身误报；不只报告总体 CER。
- 效率：CPU 上的实时率 RTF、峰值内存、缓存命中、模型首次加载时间；分别报告检测头和完整评估链。
- 端到端：同预算下人工确认的缺陷残留率、修复成功率、额外请求／字符／费用、未解决数量与质量—成本曲线。
- 选角：真实对话中的角色辨识准确率、混淆矩阵与适配偏好；展示角色映射和不展示映射的任务分别设计，不混合解释。
- 调参在开发集完成，测试集只作固定方案比较。阈值按应用误报容忍度选择；不能在测试集上挑最好 F1 后报告。
- 终评采用未参与修复选择的人工标注／独立核验，避免用同一检测器证明自己有效。
- 按书籍／场景聚类给出置信区间；听众实验还需考虑参与者重复测量。五人试听只作先导，正式样本量依任务效应和变异确定。
- 预生成候选可用于离线策略回放，但决策只能访问当时已观察的结果，所有逻辑请求和失败成本均计入；不能提前偷看所有候选后选择。

判断是否采用小模型：在相同可接受误报水平下，真实测试缺陷检出比规则更好，且运行成本可接受。如果没有增益，保留规则基线并分析数据与模型局限，不为追求“用了模型”而上线。

## 11. 开发里程碑与验收

以下按完成条件推进；人日为熟悉项目的单人投入估计，模型兼容与真实数据收集可能增加时间。

| 阶段 | 建议投入 | 交付物 | 验收条件 |
|---|---|---|---|
| P0 数据与请求底座 | 3～5 人日 | 计划、持久产物、请求账本、预算、Provider 块级可观测性 | 断点可恢复；同参新样本确实发起新请求；隐藏重试可计数；预算不透支 |
| P1 普通／角色模式统一组装 | 3～5 人日 | 原文映射、首批规范化、PCM 时间表、安全停顿、完整性检查 | 缺块／重块／错序能发现；不破坏角色原文验证；安全操作不截语音 |
| P2 质量评估 v0 | 4～6 人日 | 边界规则、VAD、声纹、音高语速、ASR 对齐与报告 | 四维可独立报告；缺依赖不假通过；人工能按时间定位试听 |
| P3 预算修复闭环 | 3～5 人日 | 受限动作、候选比较、局部重算、成本输出 | 只重算受影响区域；保留原始候选；耗尽预算后明确待复核 |
| P4 边界小模型先导 | 5～8 人日，另计数据收集 | 标注集、特征分类器、小网络、独立测试报告 | 无源样本泄漏；与规则比较；真实缺陷和误报分别报告 |
| P5 自动选角 | 4～6 人日，另计听众实验 | 探针库、互动图、锁约束分配与辨识试验材料 | 声音锁定有效；声音不足可解释降级；听众收益独立验证 |
| P6 后端扩展 | 按验证结果估计 | VoxCPM 上下文续接及依赖失效 | 不跨角色污染；不重复读 prompt；报告实际收益与代价 |

P0～P3 先形成可用闭环。P4 和 P5 共享底座，但研究假设分别验证。不能把全方案承诺为 1～2 周完成的成熟系统。

## 12. 必要测试与运行入口规划

### 12.1 首版配置草案

以下 JSON 仅说明拟支持的配置，不是已经接入程序的配置文件。阈值配置为空表示尚未校准，此时对应模型只输出辅助证据并进入复核，不能自动判定通过。

```json
{
  "schema_version": "audio-core-plan-v1",
  "execution": {"worker_count": 1, "device": "cpu", "allow_paid_requests": false},
  "reading": {"normalization": "conservative", "chunk_target_chars": 300},
  "quality": {
    "boundary_window_seconds_each_side": 2.0,
    "boundary_backend": "feature_baseline",
    "speaker_backend": "ecapa",
    "asr_backend": "sensevoice",
    "content_coverage": "full",
    "threshold_profile": null
  },
  "repair": {
    "local_first": true,
    "max_remote_quality_repairs_per_chunk": 2,
    "max_extra_requests": 24,
    "max_extra_character_ratio": 0.30,
    "max_local_actions_per_chunk": 2,
    "local_speed_factor_range": [0.95, 1.05]
  },
  "casting": {"enabled": false, "preserve_locked_voices": true},
  "context_continuation": {"enabled": false}
}
```

`allow_paid_requests` 是未来实验入口的执行开关，不取代现有用户授权与运行前预算检查。24 次追加请求仅适用于本方案的首轮样本规模，其他规模应重新配置。质量检测依赖缺失、阈值未校准等情况要与“已确认失败”分别显示。

### 12.2 测试与入口

第一阶段值得编写的测试：

1. 原文区间→规范化→分块覆盖；歧义数字与多音字不擅自替换。
2. 少块、错序、重复块、尾音裁切、静音重复添加的组装回归。
3. MiMo 本地变速不发起远端请求；MiniMax 请求配置变更导致适当失效。
4. reuse 与 resample 区别、原始缓存不随临时目录清理消失、恢复不重复选中未知请求。
5. 网络重试／内部子块均占预算，超时计费不确定不会被记为零。
6. 同角色与换角色边界区别，短语音／模型不可用返回 incomplete。
7. 修复一个块仅使相关边界与依赖报告失效，用户锁定声音始终生效。
8. 合成数据划分以原始音频为组，变体不跨训练／测试集。

开发顺序：先用 mock Provider 与固定 WAV 完成离线测试，再运行少量真实样本。CPU 评估依赖作为可选组件，模型惰性加载；建议使用隔离的 Python 3.11 环境验证，不直接升级项目 Gradio。

拟新增 `scripts/audio_research.py`，提供 preflight、render、evaluate、train-boundary、repair、cast、summarize 子命令。它们尚不存在，不能按当前可执行入口使用。preflight 仅输出缺失依赖、模型缓存状态、逻辑样本数与预算估计；任何真实调用由单独执行步骤产生。

## 13. 论文主线与证据边界

第一主线：面向黑盒 TTS 的边界感知、预算约束有声书质量控制。重点是边界与角色条件评估、修复决策及同预算下的端到端结果；规范化和组装作为受控模块与消融。

第二主线：面向听众辨识的角色互动图选角。重点是互动加权分配与真实听众辨识；固定质量与修复配置，避免把多个模块收益混在一起。

原文的证据约束角色归属可继续作为上游能力保留，但首轮修复与选角实验先固定人工核对的角色脚本，避免归属错误混淆结论。

“评估驱动纠错”“自动选角”“跨句上下文”均已有相关工作，本方案仅提出可验证的组合与研究差异；不能据此直接保证 CCF C 类发表，也不能将预期 AUC、MOS 或修复率写成已有结果。

## 14. 已核查的外部组件与相关工作

核查日期：2026-10-15。采用具体版本后，记录提交号／模型修订号和实际运行环境。

- [Silero VAD](https://github.com/snakers4/silero-vad)：预训练语音活动检测组件；不承担文字完整性判断。
- [SpeechBrain ECAPA-TDNN](https://huggingface.co/speechbrain/spkrec-ecapa-voxceleb)：声纹提取与验证；需在中文合成音上校准，不能直接把输出当作听众辨识概率。
- [SenseVoice 官方资料](https://fun-audio-llm.github.io/)：中文转写等能力；复用项目已有懒加载入口，时间定位另外适配。
- [NISQA](https://github.com/gabrielmittag/NISQA)：多维版本面向传输语音，TTS 版本预测自然度；可作比较基线。其代码与预训练权重许可不同，权重为 CC BY-NC-SA 4.0，不默认成为商业发布依赖。
- [Vox-Evaluator，AAAI 2026](https://ojs.aaai.org/index.php/AAAI/article/view/40636)：已有质量评估与纠错研究，说明不能把通用的“检测再重试”单独当作新颖贡献。
- [Automatic Voice Casting，Interspeech 2020](https://www.isca-archive.org/interspeech_2020/gresse20_interspeech.html)：已有选角表征工作；本项目需验证互动关系与听众辨识目标的增量。
- [ContextSpeech](https://arxiv.org/abs/2307.00782)：已有上下文增强长文本合成研究；后端续接必须明确自身能力、成本与效果边界。
