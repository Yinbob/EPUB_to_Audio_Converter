# 论文创新点与实现方案（EPUB → 有声书转换器）

> 本文基于对现有代码的核对：`audiobook_generator/utils/utils.py`、
> `audiobook_generator/tts_providers/voxcpm_tts_provider.py`、
> `audiobook_generator/role_script/audio_quality.py`、
> `audiobook_generator/book_parsers/epub_book_parser.py`。
> 文中"预期效果"是待实验验证的假设，不是已测得的结果。

---

## 创新点 1：长文本分块合成的跨块一致性

### 现状（代码证据）

- `split_text` 按句切块后，`voxcpm_tts_provider.py:711-735` 对每块**独立调用** `model.generate`，
  块与块之间没有任何状态传递。
- design 模式只靠固定 seed（`_resolve_seed`，行 575-585）保证一致，但 seed 只固定采样噪声，
  音色仍会随文本条件漂移。
- 最终用 pydub 直接拼接（`utils.py` 的 `pydub_merge_audio_segments`），**没有 crossfade**，
  边界处韵律与能量会突变。

### 具体实现方案（分三层，可逐级消融）

**A. 边界平滑（最低成本，先做）**

- 在块边界做等功率 crossfade（50–120 ms）。
- 静音时长按标点类型决定：句号/问号 400–500 ms，逗号 150–250 ms，段落或对白切换 600 ms。
- 实现位置：在 `pydub_merge_audio_segments` 前增加一个 `join_segments(segments, boundary_punct)`
  函数，边界标点从 `split_text` 的输出里取。

**B. 音频上下文续接（核心创新）**

- 对第 i 块，把第 i-1 块输出的末尾约 3–5 秒音频及其转写文本作为 prompt。
- 代码已有接口：hifi 模式下 `gen_kwargs["prompt_wav_path"]` / `prompt_text`（行 733-734）。
  需要新增的是"把上一块末尾切出来、用 ASR 或已知文本作为 `prompt_text`"。
- **需先确认**：VoxCPM 的输出是否包含 prompt 部分。若包含，需按时长裁掉 prompt 对应的音频，
  否则会重复朗读。
- 音色锚点仍用原始参考音频，续接 prompt 只负责韵律和语速的连续。

**C. 与并行的权衡（必须写进论文）**

- B 让同一章节内的块变成串行依赖，章节内并行失效。章节之间仍可并行
  （`audiobook_generator.py:523-530` 的 spawn 池不变）。
- 误差会沿链条传播：某块生成失败，后续块会继承其韵律。需要结合创新点 3 的质检做截断或重试。

### 实验设计

- 基线：B0 独立分块 + 直接拼接；B1 仅 A（crossfade）；B2 A+B（续接）；
  B3 整章单次生成（作为上限参考，注意 Balalaika-Longform 的结果表明长单次生成容易漏读，
  需同时报告漏读率）。
- 数据：20–30 个章节，每章取 2000–5000 字，覆盖对白与叙述。

### 预期效果（待验证）

| 指标 | 测量方法 | 预期方向 |
|---|---|---|
| 边界 F0 跳变 | 边界 ±200 ms 内 log-F0 的差分 RMS | B1/B2 明显低于 B0 |
| 边界能量跳变 | 边界前后 RMS dB 差 | B1 显著改善 |
| 音色一致性 | 相邻块与全章的 ECAPA 余弦相似度 | B2 最好 |
| 内容保真 | 块级 ASR-CER | 续接可能引入重复/漏读，需重点监控 |
| 主观 | 5 人 MOS，配对偏好 | B2 最好但耗时最高 |

**风险**：B 的收益可能被误差传播抵消；如果 A 已经解决大部分听感问题，B 的增量需要显著性检验
（配对 bootstrap，n≥20 章）。

## 创新点 2：中文有声书的朗读向文本规范化与停顿建模

### 现状（代码证据）

- `epub_book_parser.py:62-72` 只做空白合并、尾注删除、`[1]` 引用删除。
  没有数字、日期、百分比、英文缩写、单位的中文读法处理。
- `split_text` 在句子之间插入 `" "`（`utils.py:42`），中文文本中会产生无意义空格，
  其对 TTS 停顿的影响未经测量。
- 标点停顿完全依赖模型自身判断，没有显式控制。

### 具体实现方案

**模块：** 新增 `audiobook_generator/utils/zh_tts_normalize.py`，在 `split_text` 之前调用，
并保留原文供评测使用。

1. **确定性规则层**
   - 数字：年份逐位读（2026→二零二六），数量按位读（1200→一千二百），
     百分比、小数、日期、时间、单位（km、℃、GB）。推荐用 `cn2an` 这类库做基础转换，
     再补充领域规则。
   - 英文缩写与字母词：维护可配置词典（AI、CEO、iPhone），
     支持用户通过现有的 search/replace 文件覆盖。
   - 省略号、破折号：`……` 映射为显式停顿标记，`——` 映射为短停顿。

2. **多音字层**
   - 词典法：对常见多音字（行、长、重、乐等）按词组匹配。
   - LLM 消歧（可选）：只允许 LLM 返回读音选项，不允许改写正文
     （与 `audio_quality.py:158-202` 的"受限动作表"思路一致）。
     仅当 TTS 支持拼音标注时启用，否则 LLM 改写会破坏原文。

3. **停顿层**
   - 把段落边界、对白切换映射为显式静音。已有先例：
     `edge_tts_provider.py:66-152` 按 `break_string` 切段并插入静音。
   - 把对白（“”「」）与叙述区分，对白段可传入风格描述，与角色模式复用。

### 实验设计

- 测试集：200 段网络小说文本，人工标注"正确朗读文本"
  （即 TTS 应该读出的内容，而不是原文）。
- 关键点：**CER 的参考文本必须是标注后的朗读文本**，否则规范化本身会被计为错误。
- 基线：B0 原文直接合成；B1 仅规则层；B2 规则 + 停顿层；B3 规则 + LLM 多音字（可选）。

### 预期效果（待验证）

| 指标 | 测量方法 | 预期方向 |
|---|---|---|
| 数字/符号错误率 | 每千字错误数（人工标注对照） | B1 相比 B0 大幅下降 |
| 朗读 CER | 以标注朗读文本为参考的 ASR-CER | B1 下降 |
| 停顿匹配 | 用 VAD 检测静音段，与标点位置计算 F1 | B2 提升 |
| 主观 | 偏好测试 | B2 > B1 > B0 |

**风险**：规则会过度处理（如"2026年"的"年"前是否读作数字）；需要用歧义样例集做回归测试。
多音字 LLM 消歧的错误率需要单独报告。

## 创新点 3：面向有声书的客观质量评估框架

### 现状（代码证据）

- `role_script/audio_quality.py` 已有段级评估：语速（`too_fast`，4.3 字/秒）、削波、
  静音占比、ASR-CER（阈值 0.12）。
- **普通模式（`audiobook_generator.py`）没有调用它**，没有任何客观评估。
- 阈值 4.3 和 0.12 是手工设定，没有依据。
- `_error_rate`（`audio_quality.py:49-62`）是纯 Python 的 O(n·m) 编辑距离。
  对整章（上万字）会非常慢，不能直接用于章级评估。

### 具体实现方案

**分层指标**

| 层级 | 指标 | 实现要点 |
|---|---|---|
| 块 | 漏读率、增读率、替换率 | 块的文本已知，直接对块音频做 ASR 再对齐，无需全局对齐 |
| 块 | 语速、时长比 | 复用 `evaluate_segment_audio`，阈值改为校准后的值 |
| 块 | 响度 LUFS、削波、静音 | 用 pyloudnorm 测量，检查块间响度差 |
| 章 | 聚合统计、离群块 | 语速 z-score，漏读率分布，失败块比例 |
| 章（可选） | LLM-as-judge | 仅作辅助，需与人工标注做一致性检验 |

**关键工程改造**

- 把 `_error_rate` 改为 `rapidfuzz` 或 numpy 实现；如果只能用纯 Python，
  则对块级文本做字符级对齐，章级只做聚合。
- 普通模式在每块合成后调用评估，输出 JSON 报告；WebUI 增加"质检报告"页签。
- 复用角色模式已有的 `choose_quality_attempt`（`audio_quality.py:150-155`）做 best-of-N 重试，
  并统计重试收益。

**阈值校准（论文的核心贡献之一）**

- 收集人工标注的 300–500 个块（合格/不合格，并给出失败类型）。
- 对每个指标画 ROC，选取使 F1 或 Youden 指数最大的阈值，并报告 AUC。
- 用真人录音（而不是 TTS 输出）测量 ASR 自身的误差底噪，作为 CER 的下限参照。

### 实验设计

- 验证 1：指标与人工判断的相关性（Spearman）和 AUC。
- 验证 2：检测召回率与误报率，按失败类型分别报告。
- 验证 3：质检驱动重试的端到端效果：最终不合格块比例、额外耗时。
- 数据集：将标注数据集公开，这本身可以作为 CCF-C 数据集论文的贡献。

### 预期效果（待验证）

| 指标 | 预期 |
|---|---|
| 漏读检测 AUC | 0.85 以上（ASR-CER 对漏读敏感） |
| 语速检测 AUC | 与人工判断中等相关（Spearman 约 0.5–0.7） |
| 重试收益 | 1–2 次重试后，不合格块比例显著下降，但额外耗时需报告 |
| 指标-人工一致性 | 高于随机，但 ASR 误差可能导致误报，需分析 |

**风险**：ASR（SenseVoice）本身对中文文本存在误差，会把正确音频判为不合格；
必须用真人录音测底噪并在论文中讨论。LLM-as-judge 的偏置需要单独报告，不宜作为唯一依据。

## 三者的关系与推荐的论文结构

- 创新点 3 为创新点 1 和 2 提供评测手段：没有客观指标，就无法证明续接或规范化有效。
- 推荐论文主线：**"面向长文本有声书的分块合成与客观评估"**，
  以 1 为方法、3 为评测、2 为辅助模块。
- 最小可行实验（约 1–2 周）：先用 20 章做 B0 与 B1 的对比，并校准一个 ASR-CER 阈值。
  如果 B1 的边界指标没有显著差异，应转向创新点 2 或 3，而不是继续做 B2。
